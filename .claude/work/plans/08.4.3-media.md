# 08.4.3: The Media section and dialog

**Goal:** every attachment of the Space in one place, with the pages that
use it: a compact Media section under Files to find and drag files into a
page, and a large Media dialog to rename, delete and clean up unused ones.

**Specs:** `.claude/work/specs/08-documents.md` decisions 9, 10, 11, 52, 70,
96 and 97; `docs/file-format.md` (`.bava/attachments/`, `.bava/trash/`);
`docs/ipc.md`; `.ai/rules/editors.md`, `.ai/rules/file-format.md`,
`.ai/rules/wails.md`, `.ai/rules/ipc.md`, `.ai/rules/design-system.md`,
`.ai/rules/svelte.md`.

**File format impact:** one addition, specified first (Task 1): an
attachment can be in `.bava/trash/`, as a page or a folder is, and is
restored to the attachments folder. Nothing new is written about
attachments anywhere else: which pages use one, and whether it is unused,
is worked out each time from the pages (decision 11), never stored.

**UI impact:**
- **The Media section**, stacked under Files in the side pane: collapsible
  like Files, the two sharing the pane's height with a splitter between
  them. Compact rows (a small thumbnail, the name, the size); search by
  name; drag a row into the page; an Add files button; a button opening the
  dialog.
- **The Media dialog**, over the Dialog wrapper (`size="media"`): the same
  attachments larger, in a grid or a list; filters (All, Images, Videos,
  PDFs, Other, Unused); search; sort by name, size or date; each item's
  pages; rename, delete, show in folder; Add files; "Move unused to Trash".
- **Components:** `MediaSection` and `MediaDialog`, presentational; the
  item's thumbnail is `MediaThumb`. Existing: `Dialog`, `Segments` (grid or
  list, filters), `OptionPicker` (sort), `Splitter`, `EmptyState`,
  `ConfirmDialog`, `ContextMenu`.
- **Tokens:** the thumbnail sizes (row, grid), the grid's column width, the
  dialog's size.
- **The Trash dialog** lists attachments too, restorable like a page.

## Constraints

- **Files are the source of truth** (non-negotiable 2): the list is read
  from `.bava/attachments/` each time; "used by" and "Unused" are worked out
  from the Space's pages with the Document's own reader (`pageLinks`, which
  already finds media addresses, card addresses, posters, icons and
  pictures). Nothing about attachments is saved.
- **"Used" means** reached by a page of the Space (not one in the Trash):
  an image or video's address, a card's address, or a poster, icon or
  picture named in a mark. Files a user put in the folder by hand count as
  attachments here (they are in the folder); files elsewhere in the Space
  are not attachments (decision 10).
- **The date** is the file's date modified: Bava writes a file once, when
  it is attached, so that is the day it was added.
- **Deleting never loses work** (decision 11):
  - Delete, and "Move unused to Trash", move files to Bava's Trash, where
    they can be restored until the Trash is emptied (decision 70).
  - Deleting a file a page still uses asks first, naming the pages; those
    pages then show it as missing, with the relink offer (decision 96).
  - "Move unused to Trash" asks first, with how many files and their size.
- **Renaming** is the rename 8.4.1 built (`renameAttachment`, every page
  follows), from the dialog instead of the page.
- **Adding** without placing on a page uses 8.4.1's attach, several files
  at once; a loose page's Space offer does not apply (the section shows
  only in a Space).
- **Dragging a row into the page** puts it where it lands, as a drop from
  the desktop does (8.4.1), without copying: it is already an attachment.
- **Thumbnails load from the file route** (8.4.1): an image itself; a
  video's poster when it has one used by a page, else a video icon; any
  other file its type's icon (the cards' icons). Nothing is generated or
  cached.
- **Pages are read once per opening** of the section or dialog, and again
  after an attachment is added, renamed or trashed. A Space of many pages
  reads them in the background; the list shows at once and "used by"
  follows.

**Deviations from this plan:**
- **Sort is a `Segments`**, not `OptionPicker`, which is built for icons
  on the canvas.
- **"Show in folder" on an attachment never worked** (8.4.1's media menu
  included): Space paths refuse the hidden folder. `Reveal` now reaches an
  attachment by name (`AttachmentPath`).
- **The splitter's handle** is a button Ark draws; the wrapper now resets
  its border and padding (it showed as a bevelled 9 px bar) and stacks
  panels (`orientation="vertical"`).
- **Folding Files or Media lays the side pane out anew** (split, or stacked
  with one folded), so focus is put back on the fold button.
- **The Diagram dialog's reference changed** by one line's tint: the page
  now also reads the Space's attachments and pages on opening, which
  changed when the dialog's code editor took focus. The walk now waits for
  that focus; the line is drawn in exactly its token colour now, where the
  old picture had an extra highlight on it.
- **Sixty-two references changed** because the Media section shows under
  Files in every full-window shot. Each was measured against its last
  version; the differences sit in the side pane, except the menus and
  bubbles whose shots start at the tree (the Marketing folder open), the
  full-screen viewer's overlay over the side pane, and the Diagram dialog
  above. Those were looked at one by one.

**Not proved by a test:** the arrow keys across the dialog's grid (jsdom
lays nothing out, so a row's length cannot be measured there; the list's
arrows and the section's are tested).

**Spec review: FAIL, five blockers, all fixed; every warning fixed.** Four
blockers were ways a file a page uses could be called Unused and moved to
the Trash; the rule is now that a mistake only ever keeps a file:
- **Nothing is unused until every page was read.** `mediaUsage` knows
  whether the pages were all read (none missing, none `unreadable`, which
  `Index` now reports); until then no file is Unused, and "Move unused to
  Trash" is off, with a note saying why.
- **The open page counts as it is now**, saved or not (the editor's text
  replaces the file's).
- **A page that names a file anywhere uses it**: in a line of text, a list,
  a table, a heading, HTML, by reference; percent-encoded, in any case or
  Unicode form. A file named only in a code span is kept too.
- **Delete and "Move unused to Trash" read the pages afresh** before
  asking, never trusting the list on screen.
- **A listed name is acted on exactly**, never trimmed (`logo.png ` beside
  `logo.png`), and the attachments folder, or `.bava`, being a link is
  refused (`ErrThroughLink`).
- Also: a restored file that came back numbered says so; a failed listing
  says so; the dialog is one stop for Tab, the arrows moving and choosing;
  dates in local time; the dialog's size fits a small window; the share's
  limits in one place (`MEDIA_SHARE`); placing from the section only into a
  shown page; a new refusal code, `notAttachment`, worded in the app.
