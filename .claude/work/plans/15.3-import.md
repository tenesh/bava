# 15.3: Import

**Goal:** bring Markdown files, folders and Bava's own export zips into a
Space, and let long imports and exports count and cancel.
**Specs:** `.claude/work/specs/import.md` (decisions 1 to 11),
`.claude/work/specs/documents.md` decision 49, the roadmap's 15.3; the
screens on the mockup canvas, page "7 · Import".
**File format impact:** none. Imported pages are copied as written; only the
addresses that must change are rewritten (decision 9).
**UI impact:** a new `ImportDialog` (the Export Space layout: `ZipContents`,
`Select`, `Progress`, `Dialog`); File ▸ Import and a folder's right-click
Import, each with Files and Folder; progress and Cancel in Export Space.

## Constraints

- What comes in: Markdown files and folders, their pictures and every other
  file copied into `.bava/attachments`; a Bava export zip with its pages,
  attachments and templates. Hidden files stay behind, except the `.bava`
  of a folder that is itself a Space. A zip's or Space's `space.json` is
  never read (decisions 3, 4, 8).
- Where: the folder chosen. A folder comes in whole ("Q4 notes"); Files
  brings pages straight into the folder (decision 11).
- Clashes: keep both; the incoming one is numbered (`Q4 notes 2`, `Launch
  plan 2`), never overwritten; attachments reuse identical bytes and number
  a different file with a taken name (decision 10 of documents.md); a
  template clash is numbered too (decision 4).
- Links among the pages of one import follow a renamed page; pages already
  in the Space are never touched (decision 1).
- A picture from outside the import is copied in; out of reach in a store's
  sandbox, it stays a missing picture with its link kept, never a failed
  import (decision 2).
- Pages are copied byte for byte except those addresses (decision 9).
- Progress "Importing 5 of 12" with Cancel; Cancel removes what this import
  added, leaving a reused attachment (decision 5). Export: a zip counts
  "Writing 34 of 210" with Cancel, which removes the unfinished zip; a
  Space's PDF can be cancelled while it prints (decision 10).
- Entry points, the same on every system: File ▸ Import ▸ Files and
  ▸ Folder, and a folder's right-click Import ▸ Files and ▸ Folder; both
  disabled with no Space open (decisions 6, 7).
- A link is read by one reader, the page's (`docs/markdown.ts` `pageLinks`):
  Go copies and names, the frontend rewrites addresses, as moves do today.

## How it works

1. The user picks Markdown files or a zip (File ▸ Import ▸ Files) or a
   folder (▸ Folder). Every pick is allowed through the access store, as
   all picks are.
2. Go plans it (`SpaceService.ImportPlan`): what comes in, where, which
   names are numbered, the counts and size. Nothing is written.
3. The Import dialog shows the plan; "Into" re-plans for another folder.
4. Import: Go copies (`SpaceService.Import`, cancellable through its
   context), sending progress events, and returns each imported page's new
   path and where it came from, and which attachment each copied file
   became.
5. The frontend reads each imported page with `pageLinks`, rewrites its
   pictures' and files' addresses to `.bava/attachments`, copies in pictures
   from outside the import, follows renamed pages, and writes the edits as
   moves' relinks do (`WriteIfUnchanged`).

## As built (2026-10-12)

File ▸ Import ▸ Files and ▸ Folder, and a folder's right-click Import, pick
pages and zips (the system's own dialog, Markdown and zip only) or a folder.
Go plans the import (`space.Space.ImportPlan`): a folder comes in whole,
pages straight into the folder chosen, a zip keeping its folders; hidden
files and links stay behind; a Space's or Bava zip's attachments and
templates come, never its settings or Trash; every clash is numbered by the
one shared `space.FreeName` / `FreeFolderName`. The Import dialog shows it as
it will land (an export's zip preview, fed by `files/import-preview.ts`),
"Into", and what was renamed. Import plans afresh, writes pages byte for
byte, attaches every other file (identical bytes reused), saves templates,
sending `progress`; Cancel undoes it. The page side then rewrites only the
addresses that must change (`files/import-links.ts`, on `pageLinks`) and
writes them as relinks do. Export Space's zip counts "Writing N of M" and
cancels; its PDF says "Printing N pages" and cancels between pages.

**Deviations**
- **`Import` takes the picks, not a plan:** it plans again when it runs, so
  a name taken since the dialog showed is numbered, and the page cannot hand
  Go a stale or altered plan.
- **What the dialog shows** comes from the zip preview the exports use: the
  tree as it lands, a Space's attachments and templates counted in its
  hidden line. An empty folder in what comes in does not show.
- **"Into" is disabled while the plan is read** (and while importing): a
  plan landing on an open list made Enter pick the old choice, about one
  run in three in the browser tests. Two fixes inside `Select` (a stable
  value array, a collection rebuilt only when its options change) changed
  nothing and were reverted; the cause inside the list was not found.
  `Select` gained a `disabled` prop and a disabled look for this.
- **The progress bar beside its count** (`--size-progress-inline`): at full
  width it had no room beside the text and vanished; Export Space's
  "Drawing N of M" had the same flaw, fixed with it.
- **A Space's PDF was already stopping on a cancel**, by accident: the PDF
  library fails on a cancelled context while counting sheets. It now checks
  between pages itself, and the bound method reported that cancel as a
  failed page: it now says `cancelled` first.
- **The end-to-end walk imports into a new folder of the Smoke Space**, not a
  new Space: no menu command makes a Space. It still proves the round trip
  and checks an address rewritten one folder down and a template numbered.
- **A picture from outside an import** is attached through the existing
  `attach` operation; the browser stand-in has none, so there it stays as
  written (the sandbox's behaviour), and the unit and Go tests cover the
  copy.
- **The stray `internal/space/relative.zip`** is untouched (out of scope).

**Red first:** every Go test (names, planning, importing and its undo, the
IPC methods, the zip's progress and cancel, the PDF's cancel), the store's,
the rewriting's, the preview's, the menus', the dialogs' and the browser
integration tests were seen failing first. The zip's and planning's tests
were also checked by breaking the code on purpose (numbering off, undo
off). The PDF's cancel test passed before any change, which is how the
accidental stop was found.


**Review** (spec-reviewer: FAIL, two blockers and fourteen warnings; each
checked before acting):
- **Cancel never reached the page as a cancel** (blocker): the runtime's
  own cancel rejects the call's promise at once and drops Go's answer, so
  an import showed an error, and the page would claim "nothing was added"
  while Go was still undoing, or after an import that had just finished.
  The stand-ins resolved instead, which hid it. Now each long task gets a
  name from the page (`ipc/runs.ts`), `SpaceService.Cancel(run)` stops it
  (`app.Runs`, shared with the ExportService, which also stops a run whose
  Cancel arrived first), and the call itself answers `cancelled` once undone.
  The stand-ins stop runs the same way.
- **An address could climb out of a zip or a drive** (blocker): `../`
  past a zip's top, or past `C:`, became a relative path handed to
  `attach`. Places now keep their root (`/`, a drive, a network share, a
  zip) and are null above it; a picture from outside the import is copied
  only for a picture or video type outside hidden folders; Go's `attach`
  refuses a relative source.
- Escape while a run is under way stops it and the dialog stays until it has
  (`Dialog` gained `dismissible` and `onEscape`); Cancel is off once
  everything is in and only the links are being written.
- A second import or export waits until the one under way is done.
- Found in the new pictures: Export Space's settings stayed live while it
  wrote or printed. They now sit in a fieldset disabled meanwhile (Ark's
  controls follow it), and `Segments` and `NumberField` gained the disabled
  look buttons have.
- Undoing an import takes only the template folders it made: an empty group
  the Space had stays, a templates folder it made goes.
- A name the Space would trim stays behind inside a folder or zip; a page or
  folder picked by such a name lands under the trimmed name.
- A linked `.bava`, `attachments` or `templates` folder is never followed.
- A zip's file at its top no longer takes, or renames, a name in the folder.
- Imported files are streamed into the attachments, never held whole.
- Import says it needs a Space in its own words (`import.noSpace`).
- Tests added for zip entries that leave the zip or are links (the code
  already refused them), and pictures of Export Space writing and printing.
  A test fixture named after another app's settings folder was renamed.
- Pushed back: nested names that differ only in case (on a disk that ignores
  case the second merges into the first; nothing is lost, and it is rare);
  a Windows link differing in case from its file (it stays as written, which
  is safe); an empty folder inside a zip (Bava's own zips hold none, so a
  round trip is whole). Names skipped because a Space cannot hold them are still not
  listed in the dialog: saying so is new UI, owed a design first.

**Second review** (spec-reviewer: PASS, five warnings, four fixed):
- Run names are random, so a page reloaded while Go runs on never reuses
  one, and a run's end removes only its own entry.
- A folder that cannot be read no longer has every name taken: numbering
  used to loop forever there; now the write fails and says why.
- An address holding a backslash is never followed: some systems read it as
  a folder, which slipped past the hidden-folder check.
- A cancel stops a file mid-copy instead of waiting for it to end.
- A Space's PDF being drawn also holds back a second import or export.
- Names inside what comes in that differ only in case ("A.md" and
  "a.md", in a zip or a folder from a disk that tells them apart) are
  numbered and listed as renamed: a disk that ignores case made the whole
  import fail before. The folder case is proven where the disk tells case
  apart (Linux CI); here it skips.
