# 15.3: Import

**Goal:** bring Markdown files, folders and Bava's own export zips into a
Space, and let long imports and exports count and cancel.
**Specs:** `.claude/work/specs/import.md` (decisions 1 to 11),
`.claude/work/specs/documents.md` decision 49, the roadmap's 15.3; the
screens on the mockup canvas, page "7 · Import".
**File format impact:** none. Imported pages are copied as written; only the
addresses that must change are rewritten (decision 9).
**UI impact:** a new `ImportDialog` (the Export Space layout: `ZipContents`,
`Select`, `Progress`, `Dialog`); File ▸ Import and a folder's right-click
Import, each with Files and Folder; progress and Cancel in Export Space.

## Constraints

- What comes in: Markdown files and folders, their pictures and every other
  file copied into `.bava/attachments`; a Bava export zip with its pages,
  attachments and templates. Hidden files stay behind, except the `.bava`
  of a folder that is itself a Space. A zip's or Space's `space.json` is
  never read (decisions 3, 4, 8).
- Where: the folder chosen. A folder comes in whole ("Q4 notes"); Files
  brings pages straight into the folder (decision 11).
- Clashes: keep both; the incoming one is numbered (`Q4 notes 2`, `Launch
  plan 2`), never overwritten; attachments reuse identical bytes and number
  a different file with a taken name (decision 10 of documents.md); a
  template clash is numbered too (decision 4).
- Links among the pages of one import follow a renamed page; pages already
  in the Space are never touched (decision 1).
- A picture from outside the import is copied in; out of reach in a store's
  sandbox, it stays a missing picture with its link kept, never a failed
  import (decision 2).
- Pages are copied byte for byte except those addresses (decision 9).
- Progress "Importing 5 of 12" with Cancel; Cancel removes what this import
  added, leaving a reused attachment (decision 5). Export: a zip counts
  "Writing 34 of 210" with Cancel, which removes the unfinished zip; a
  Space's PDF can be cancelled while it prints (decision 10).
- Entry points, the same on every system: File ▸ Import ▸ Files and
  ▸ Folder, and a folder's right-click Import ▸ Files and ▸ Folder; both
  disabled with no Space open (decisions 6, 7).
- A link is read by one reader, the page's (`docs/markdown.ts` `pageLinks`):
  Go copies and names, the frontend rewrites addresses, as moves do today.

## How it works

1. The user picks Markdown files or a zip (File ▸ Import ▸ Files) or a
   folder (▸ Folder). Every pick is allowed through the access store, as
   all picks are.
2. Go plans it (`SpaceService.ImportPlan`): what comes in, where, which
   names are numbered, the counts and size. Nothing is written.
3. The Import dialog shows the plan; "Into" re-plans for another folder.
4. Import: Go copies (`SpaceService.Import`, cancellable through its
   context), sending progress events, and returns each imported page's new
   path and where it came from, and which attachment each copied file
   became.
5. The frontend reads each imported page with `pageLinks`, rewrites its
   pictures' and files' addresses to `.bava/attachments`, copies in pictures
   from outside the import, follows renamed pages, and writes the edits as
   moves' relinks do (`WriteIfUnchanged`).

### Task 3: Carrying an import out, and undoing a cancelled one
**Files:** `internal/space/import.go`, `import_test.go`.
**Behavior:** `(s Space) Import(ctx, plan, progress func(done, total int)) (ImportResult, error)`
creates folders, writes pages byte for byte, attaches every other file
(identical bytes reuse the existing one), saves templates, calling
`progress` after each. A cancelled context stops it and removes everything
it created, leaving reused attachments. The result maps each page's new
path to its source, and each copied file to its attachment's name.

Markdown); undo of a finished import (its pages go to the Trash like any
other); progress on a single page's PDF; the stray `internal/space/relative.zip`
test leftover.
