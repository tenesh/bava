# 08.4a: Canvas testing pass

**Goal:** everything the canvas draws and does is checked by a machine, in
both themes and at two zooms, so embedding it in the Document (8.5) cannot
break it unseen; the window checks still owed from Milestones 6 and 7 are
replaced, each by a named check, or kept for a person with a reason.

**Specs:** `.claude/plan/roadmap.md` (8.4a); `.claude/work/plans/06-canvas.md`
and `07-snapping.md` (every "Verification" section: the owed checks);
`docs/file-format.md` ("The canvas"); `.ai/rules/testing.md`,
`.ai/rules/canvas.md`, `.ai/rules/design-system.md`.

**File format impact:** none.

**UI impact:** none planned. A defect a check finds is fixed test-first in
this milestone, and listed in the As built.

## Constraints

- **Checks, not new behaviour.** Production code changes only to fix what a
  check finds. What the checks need lives in the test harness, or in the
  smoke build (`-tags e2e`), never in a release build.
- **Seeded canvases never touch the Files tree.** A walk puts its scene into
  an existing page of the pretend Space before opening it, so the 170-odd
  existing screenshots do not change.
- **Two zooms:** 100% and 200% (`view.actualSize`, then `view.zoomIn`), for
  the looks and states where size matters (strokes, heads, labels, handles,
  code text). Zoom-dependent behaviour (a drag threshold, the snap reach) is
  also checked at 25%.
- **Every screenshot is looked at before it is kept.**
- **A check asserts what the saved file holds** wherever it can (save, then
  read the scene back), not only how it looks.
- **What a machine cannot judge stays at the window**, named in the As built
  with the reason: smoothness while dragging a few hundred elements; a PNG
  copied into another app; an SVG's text in a vector editor.

## As built

**Shipped.** The harness seeds a scene into an existing page, reads the saved
scene back (waiting for the exact `saved` state, which `unsaved` contains),
and records exports with their bytes; its Render stand-in lays out one box
for typed code, the dialog's starting code still laying out as nothing.
`canvas-scenes.ts` holds nine scenes plus two for the states walk. Three new
walks: `canvas-look` (18 tests, 36 references: each scene, both themes, at
100% and 207%), `canvas-states` (28 tests, 81 references), `canvas-actions`
(47 tests, each asserting on the saved file). The smoke driver's `key` and
`drag` steps take `modifiers` (`shift`, `alt`, `mod`), and a `file` step has
the host read a page back from the scratch folder through `os.OpenRoot`
until it holds the text; `tests/e2e/scenarios/canvas.json` draws, attaches,
moves, undoes and redoes, inserts a diagram through the real renderer, saves,
checks the file and reopens, and CI runs it after `create` and `reopen`.

**Defects the checks found, each fixed test-first:**
1. A faded shape broke the page when its pane was hidden: a filled, outlined
   shape below full opacity draws through Konva's off-screen buffer, sized to
   the stage, and WebKit throws drawing a buffer of no size. The stage keeps
   its last size while hidden and is never mounted at nothing (`stage.ts`).
2. A word wider than its box was cut ("orang"), where the rule and the export
   draw it whole: Konva 10.5 cuts any line wider than a fixed width, even with
   wrapping off. Labels and free text are widened to their widest line, the
   way the alignment says (`overflowBox`, `text-layout.ts`).
3. The toolbar began with a divider when it had no colours (code blocks,
   groups).
4. With the right-click menu open, arrow keys and Space moved the selected
   shape: the menu takes focus a moment after it opens. Canvas keys stand
   down while any menu is open (`canvasKeyStandsDown`).
5. No picker showed the choice in effect when it was a default, alignment
   worst of all, its default differing by kind. `shownProperty` replaces
   `currentProperty`, counting an absent key at its default, the
   alignments' taken from the drawing code (`defaultAlign`,
   `defaultVerticalAlign` in `paint.ts`).
6. CodeMirror's dotted focus outline showed round the Diagram dialog's code
   in light (`editor/theme.ts`).

**Deviations and findings.**
- Zoomed pictures are at 207% (four steps of 1.2), not 200%, panned so the
  scene's corner is in view; the tool rail covers the canvas's left edge, so
  scenes start clear of it.
- Headless WebKit can keep painting a menu or popover as it first appeared
  after a highlight moves or a choice changes, though every computed style has
  changed; a resize does not repaint it. Which row is highlighted or checked
  is asserted from the page; submenus are pictured in dark only, opened from
  the keyboard, and light's is a window check (`.ai/rules/testing.md`).
- `selectNext`/`selectPrevious` (`canvas/selection.ts`) have had no callers
  since Tab was left to the browser's focus; left for a later tidy.
- The `canvas` smoke scenario could not be run from this machine's shell (the
  window never progressed); it runs on CI first. That the arrow follows the
  moved box is shown by its `moved` screenshot only; that it follows is
  asserted on the file by `arrows › an arrow drawn between two shapes…`.
- **Spec review: FAIL, then fixed.** The blocker: a frame's label draws at
  the top when the file says nothing, but writing treated `middle` as the
  default, so choosing Middle on a frame cleared the key and it stayed at the
  top. `defaultFor` now gives a frame `top` (test in `style.test.ts`), and
  `docs/file-format.md` records the frame defaults. The warnings, all taken:
  the stage uses the shared alignment defaults; the Diagram dialog's code pane
  shows focus with the token ring instead of CodeMirror's dotted outline (not
  none); test groups named by behaviour; the Reload check now asserts the
  right-click's event is prevented, which is what keeps the webview's menu
  away; the symlink case skips alone; `main_e2e.go`'s comment names the
  scratch folder as the only one a `file` step reads.
