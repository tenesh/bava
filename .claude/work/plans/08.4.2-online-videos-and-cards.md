# 08.4.2: Online videos and cards

**Goal:** YouTube, Vimeo and Loom videos show in the page and load only when
play is pressed; any other file, and any web link pasted on its own line,
becomes a card that can be switched to a plain link or an extended card.

**Specs:** `.claude/work/specs/08-documents.md` decisions 32 to 37, 52, 94,
95, 96 and 97; `docs/file-format.md` ("Images and videos", "Invisible
marks", `.bava/attachments/`); `docs/ipc.md`; `.ai/rules/editors.md`,
`.ai/rules/file-format.md`, `.ai/rules/wails.md`, `.ai/rules/ipc.md`,
`.ai/rules/design-system.md`.

**File format impact:** yes, specified first (Task 1).
- **Online video:** the image form, as decision 94 has it:
  `![Launch demo](https://www.youtube.com/watch?v=abc123)`, its width,
  ratio, alignment and caption in the mark above.
- **Card:** a link alone on its line with `card` or `card=extended` in the
  mark above (decision 95). A web card's saved details are in the mark too:
  `description="…"`, `icon="<file>"`, `image="<file>"`, each picture a file
  in the attachments, named like a poster (the name only).
- **A plain link** has no mark, so switching a card to a link removes it.

**UI impact:**
- **Blocks:** an online video block (a placeholder until play), and a card
  block (simple and extended, for a file and for the web).
- **Menus:** the card's menu (Link, Card, Extended card, Refresh details for
  a web card, Replace, Rename file, Show in folder); the online video's menu
  (Width, Shape, Align, Caption, Open in browser).
- **`/` gains** File, Web link and Online video, in Advanced. Web link and
  Online video ask for an address in the field the caption uses
  (`LinkField`).
- **Components:** none new. Icons for file types come from Lucide, which the
  app already bundles.
- **Tokens:** the card's sizes (icon, picture, the extended card's height).

## Constraints

- **Network only on the user's action** (non-negotiable 1, decisions 32 and
  36):
  - An online video contacts its site only when play is pressed. Before
    that it is a plain placeholder: the provider's name, the address, and a
    play button. No thumbnail is fetched.
  - A web card's details are fetched once, when the link is pasted or
    Refresh details is chosen, and saved with the card. Opening the page
    fetches nothing (its pictures are attachments).
  - Offline at paste time, the link stays a plain link (decision 36).
  - The fetch sends no cookies and no identifier: a fixed `User-Agent` of
    `Bava`, with no version.
  - Images on the web keep loading when shown, as 8.4.1 left them
    (decision 35).
- **The fetch is bounded:** `http` and `https` only; 8 seconds in all; at
  most 5 redirects; at most 1 MB of the page read (its `<head>` is enough);
  each picture at most 2 MB, and only PNG, JPEG, GIF, WebP, SVG or ICO.
- **Providers:** YouTube (`youtube.com/watch?v=`, `youtu.be/`,
  `youtube.com/shorts/`), Vimeo (`vimeo.com/<id>`) and Loom
  (`loom.com/share/<id>`). YouTube plays from `youtube-nocookie.com`. Any
  other video page is a web card (decision 37: no other embeds).
- **Playing in the page is tested first** (decision 32), on all three
  platforms (Task 2). A provider that refuses to play inside Bava's window
  opens in the browser instead when play is pressed, and the plan's As built
  says which.
- **Opening a file from its card** opens it in its own app, and only a file
  inside a folder the user opened. A program or script (`.app`, `.exe`,
  `.bat`, `.cmd`, `.com`, `.msi`, `.sh`, `.command`, `.ps1`, `.jar`, or a
  folder) is shown in its folder instead: one click never runs code.
- **Files are the source of truth:** an untouched page still saves byte for
  byte, including hand-written links with a `card` mark. A file's size, type
  and date are read from the file, never written (decision 95).
- **Renames follow:** a card's address follows page moves and attachment
  renames like a link's; `icon` and `image` follow attachment renames like
  `poster`.
- **Adding:** pasting a web address alone on an empty line makes, by the
  address: an online video, an image (by its file type), or a web card.
  Pasted inside a line of text it stays text, as today. Dropping or picking a
  file that is not an image or a video makes a file card (8.4.1 left those
  out). A loose page first offers to open its folder as a Space (decision
  52).

## As built (2026-09-29)

Gates, each by its exit code: `go vet` (and with `-tags e2e`), `go test

**Deviations from this plan:**
- **Task 2's check at the window runs last.** Playing needs reading,
  drawing and adding in place, so the smoke run presses play on a YouTube
  video (Big Buck Bunny, Blender's) and keeps a screenshot after 8 seconds
  on each platform. Until those are read, every site plays in the page;
  `playsInPage` (the editor's option) is where a site that refuses goes to
  the browser instead.
- **`SpaceService.FetchCard`** is its own call rather than an `Apply` kind:
  it returns details, not a change to the Space. Outside a Space it returns
  the title and description and keeps no pictures, so a pasted link on a
  loose page needs no offer to open its folder.
- **An online video's words start empty** (`![](https://…)`): its title is
  not fetched, since nothing is fetched before play.
- **A link whose words are its address is written `<https://…>`** by the
  existing writer; a card's fetched title replaces it.
- **The smoke driver gained a `pause` step**, for the player to load.
- **`LinkField` applies on Enter from its key handler** too, as the smoke
  driver's key submits no form.
- **Selecting a block for its menu** selects an image, a video or a card
  whole; it had put the caret in the block after (so in 8.4.1 an image's
  menu ringed the next block).
- **A selected image or video is ringed at the picture**, not across the
  column.

**Not proved by a test:**
- Whether each site plays inside Bava's window: the smoke screenshots, then
  your look on macOS.
- The real fetch against real sites: `internal/web` is tested against a
  local server only.

**Failing first:** every behaviour above had its test run red before the
code, for the reason named (no module, no view, kept as text, no method).
Three tests written first proved nothing when their code was switched off
and were rewritten until they failed without it: the card's click and
in-place update (checked by switching each off), and the fetcher's
network, page-size and time limits (review finding, below).

**Spec review: FAIL, two blockers, both fixed; every warning fixed or
answered.**
- **A card could run a program** (no extension, `setup.exe.`, script types
  missing from a list of programs): `OpenFile` now opens only document
  types on a list and shows anything else in its folder, and neither it
  nor `FileDetails` goes through a link.
- **Most web cards' icons never loaded**: the file route now serves `.ico`,
  and a saved icon that will not load gives way to the web's own.
- Also fixed: a public page cannot send Bava into the user's own network
  (its pictures and redirects may not reach a private address, checked
  when the connection is made); outside a Space no pictures are fetched;
  a locked page fetches nothing; Vimeo plays with `dnt=1`; a card's
  position is found again after Refresh or Replace waits; a card's `icon`
  must be a plain file name; a line's colours and unknown keys survive the
  switch to a card and back; Enter opens a selected card; a card for a page
  of the Space opens it in Bava; a failed open is worded, never Go's text
  (it names the file, so it is not logged either); comments back in place;
  the decision row says the play check is pending. *Resolved since:* YouTube
  opens in the browser (`docs/decisions.md`, `884e711`).
- **The e2e bindings** had been deleted by regenerating bindings; they are
  back, and the repo-state section now says how that happens.
