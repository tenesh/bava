# 08.4c: Full visual coverage

**Goal:** every component, canvas element, document block and app surface is
pictured in every state it can be in, in both themes, and a test fails when
something new is added without its pictures.

**Specs:** `docs/testing.md` ("The standard", "What the screen checks
cover"); `.ai/rules/testing.md`; `.ai/rules/design-system.md` (the component
inventory and states).

**File format impact:** none. **UI impact:** none planned; a defect a picture
shows is fixed test-first and listed in the As built.

## Constraints
- The standard in `docs/testing.md` holds for every new walk: helpers only
  from `specs/helpers.ts`, crops to what is pictured, state asserted before
  each picture, pointer moved off, no fixed sleeps.
- Screen checks run only in Docker; every new picture is read before it is
  kept, then again by the visual-reviewer.
- One commit at the end; the gates pass after each piece.

## Tasks
### Task 1: Component gallery (done: 52 components, 160 states, 320 pictures)
A test-only page in `frontend/tests/visual/harness/` that mounts every
`frontend/src/components/*.svelte` in each state it can show (rest, hover,
focus, pressed, disabled, checked, open, empty, error, loading as they
apply); `specs/gallery.spec.ts`, area `gallery`, one picture per component
and state group, both themes. A guard test fails when a component file has
no gallery entry.
- [x] Green: `npm run visual`, every picture read

### Task 2: Canvas, every element in every state (done: 244 pictures, area `canvas-elements`)
Each element kind (every shape, line, arrow, stroke, text, code, frame,
group): rest, selected, a handle hovered, locked, turned, a long label, its
label or code being edited, a detached binding, under the eraser; the empty
canvas, the zoom menu, tooltips; at 100% and 200% where size matters. A
guard test reads the element kinds from `canvas/scene.ts` and fails on one
not pictured.
- [x] Green, every picture read

### Task 3: Document, every block in every state (done: 234 pictures, area `document-blocks`)
Each block type from the page schema: rest, selected, hovered with its
handle, being edited, an error where it can have one; the link field and
the caption field. A guard test reads the block types from the schema.
- [x] Green, every picture read

### Task 4: The rest of the app (done: 102 pictures)
The splash; a splitter dragged; status notices; a pane that failed to draw;
each kind of unexpected error; settings with values other than the
defaults; dialog validation errors, a D2 error, each export state, renaming
in Media; the Files tree's right-click menu, a rename and a drag.
- [x] Green, every picture read

### Task 6: The defects the pictures found
Collected from Tasks 1 to 4, each fixed test-first (a picture or a unit test
that fails before), the affected references regenerated once and read. From
Task 1: the switch has no focus ring or hover; segments ring after a click,
and hover equals chosen in dark; the Files tree rings its first row unasked;
Escape while renaming in Media closes the dialog; mixed colour chips draw
blank; a custom colour opens with Default checked; field placeholders have no
token; the Shortcuts dialog's third column sits higher; the insert panel's
top-level tiles and its empty message; a long page name cut without an
ellipsis; menu styles living only in ContextMenu; and the minor ones (find
bar arrows' disabled look, a disabled toggle's track, the emoji picker's
loading state, shared arrowhead icons, New Space's long path, the start
screen's inset, the splitter's 1px target, fixed trigger ids). Disclosure is
unused: delete it.
From Task 2: the code editor draws in a system monospace and its own
colours, unlike the drawn block, and covers the language tag; a selected
arrow's middle handle sits on its label; a selected arrow hides its
detached-end marker under the end handle; the eraser walk's file read-back
belongs in `canvas-actions`. Not defects but design, kept for Milestone 15's
"labels that fit their shape": long labels dropping lines and crossing
curved outlines, a frame's long label over its contents, a long label
hiding a short arrow, the person shape's label over its head, resize
handles with no hover look.
From Task 3: ⌘K over an existing link opens the field empty, and Remove
link is offered on text with no link; the bubble in a toggle's summary
offers marks the summary cannot take, and an empty summary says "Type / for
commands"; the caption and file-name fields open at the block menu's anchor,
over the line above and the card's title; the bubble shows no active state
for colour or highlight.
From Task 4: a D2 error is listed but never marked in the editor (the
effect reads `pane` before it exists); New Space's and Media's refusals show
only in the status bar behind the dialog; the reloaded-window error repeats
its body as details with an empty label; the AI pane says "Nothing on the
canvas"; a save Go refuses shows nothing and autosave keeps trying.
Seen once, to watch: `document.spec.ts` "a web card's menu, open at Show as"
failed in one full run while other gates ran at the same time.

### Task 5: The coverage grid
`docs/testing.md`'s table becomes a grid of each thing by each state, kept
true by the guard tests of Tasks 1 to 3.
- [x] Gates by exit code; the visual-reviewer over every new picture; the
  spec-reviewer; the report

## Out of scope
Changing how anything looks. A picture that shows something wrong is
reported, and fixed only when it is a defect against the specs.

## As built

**Coverage.** 881 screen checks (was 308), every reference read before it
was kept and the changed ones read again by the visual-reviewer:
- `gallery`: every component in `src/components/` (51 after Disclosure was
  deleted) in each state it can show, both themes, on a test-only page
  (`frontend/tests/visual/harness/gallery*`) that never ships.
- `canvas-elements`: every element kind in every state that can be shown
  (rest, selected, a handle hovered, locked, turned, a long label, editing,
  a detached end, under the eraser), at 100% and 200% where detail matters.
- `document-blocks`: every node and mark of the page schema at rest,
  hovered, selected, editing, empty and in error where each applies; the link
  and caption fields.
- The rest of the app: the splash, the Files/Media splitter, every status
  notice, a failed pane, every unexpected-error kind, settings off their
  defaults, dialog refusals and export states, the Files tree's menus, rename
  and drag.
- Guard tests (`harness/gallery.test.ts`, `canvas-elements.test.ts`,
  `document-blocks.test.ts`) read the components, `ELEMENT_TYPES` and the
  schema, and fail when one has no picture on disk in both themes, or when a
  left-out entry has no reason. The coverage table in `docs/testing.md` says
  covered for every row, or exactly what is left and why.

**Defects the pictures found, fixed** (each with a test that failed first, or
the picture that shows it): focus rings only on keyboard focus (Toggle,
Segments, OptionPicker, StyleBar through `press-modality`; the Files tree);
a placeholder colour token; the chosen segment in dark; `color-scheme` per
theme so native controls follow it; mixed colour chips hatched; a custom
colour opens with no swatch checked; the Shortcuts dialog's columns level;
the insert panel's rows and empty message; page header crumbs that shorten,
then fold into a "…" reachable by Tab; find bar arrows; the emoji picker's
loading bar; New Space's long path cut from its start; the start screen's
inset; a wider splitter target; unique picker trigger ids; shared menu styles
in `styles/menus.scss`; distinct drawn icons for every arrowhead and for the
start and end head triggers; the code editor in Geist Mono with the canvas's
syntax colours, its tag showing and no chrome while it is open, and a
selected code block's outline gapped behind its tag; the arrow middle handle
beside the label (a new decision, the user's choice, replacing the
2026-09-26 row) and a detached end's handle in the danger colour; ⌘K over a
link opens with its address, Remove link only on a link; the bubble offers
only marks the line can take and shows colour and highlight as active; an
empty toggle summary says "Toggle"; caption and card-name fields open on what
they edit; D2 errors marked in the editor; refusals and failures shown in the
New Space and Media dialogs; Escape in Media's rename leaves the rename; the
reloaded-window error without details and a body that does not promise them;
the AI pane's own empty text; a refused save reported and pausing autosave; a
right-clicked tree row marked; an in-house `Portal` for the bubble, link
field and slash menu, which could read a dropped anchor and crash or stay
mounted; Disclosure deleted (unused).

**Not defects, kept for Milestone 15** ("labels that fit their shape"): long
labels dropping lines and crossing curved outlines, a frame's long label over
its contents, a long label hiding a short arrow, the person shape's label on
its head, resize handles without a hover look.

**Reviews.** Spec-reviewer: FAIL on two blockers, both settled: the middle
handle contradicted a recorded decision (the user chose the new behaviour;
recorded 2026-10-04), and the screen-check evidence (two full runs, 881
passed, exit 0, "Unused references: none"). Its fourteen warnings fixed.
Visual-reviewer: every changed reference matched an intended fix; seven
findings fixed (a tooltip race, a segment ring after a click, gallery crops,
the dark number spinner, the code block's chrome, an image crop, the error
dialog's copy). A walk that flaked under load (a web card's menu) now waits
for the block to stay put before its menu opens.

**Left, to take up separately.** (`EquationField`, `EmojiPicker`, `LinkCard`
and `DatePicker` were moved to the in-house `Portal` afterwards, with
`components/portal.test.ts`, which failed first.) While the code editor is
open the pointer can still press a handle the stage no longer draws (the
press commits the editor first). Two pairs of references disagree because
headless WebKit painted one of them stale: the disabled "Only selected"
toggle's fade (`dialogs/export--canvas` against `export--scale-*`) and the
arrowheads chip (`gallery/option-picker--rest` against `--more`).
