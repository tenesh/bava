# 08.3c: Links between pages, and date chips

> Historical: built and committed; see the roadmap for what followed.

**Goal:** a page links to another page, or to a heading on it, from the `@`
menu. Links follow the page when it is renamed or moved, and each page lists
the pages that link to it. Dates are chips changed with a calendar.

**Specs:** `.claude/work/specs/documents.md` decisions 4, 39, 40, 44, 59,
60, 77, 82, 87 and 88; `docs/file-format.md` ("The document", "The contents
block"); `docs/ipc.md` (SpaceService); `.ai/rules/editors.md`,
`.ai/rules/file-format.md`, `.ai/rules/ipc.md`, `.ai/rules/design-system.md`,
`.ai/rules/svelte.md`, `.ai/rules/testing.md`.

**File format impact:** yes, specified first (Task 1):
- **Page links:** ordinary Markdown links, so nothing new for other apps.
  What is new is written down: the relative path, `%20` encoding, and the
  text following a rename.
- **Date chips:** `<time datetime="YYYY-MM-DD">readable date</time>`.

**UI impact:**
- **The `@` menu:** pages and dates, drawn by the existing `SlashMenu`.
- **A date chip:** in the text; a click opens a calendar.
- **A link card:** a click on any link shows its address with Open, Edit and
  Remove (see Task 6).
- **"Linked from":** a list at the bottom of the page.
- **Copy link to heading:** in a heading's block menu.
- **Components:**
  - new `DatePicker`, wrapping Ark UI's date picker;
  - new `LinkCard`;
  - both go in the design-system inventory.
- **Tokens:** for a chip and a missing link, added before their styles.

## Constraints

- **Space only** (decision 4). Outside a Space:
  - `@` offers dates only;
  - there is no "Linked from" list;
  - a relative link still opens its file when it exists.
- **Nothing written for backlinks** (decision 39): they come from reading the
  Space's pages, never from a file of their own.
- **Link form** (decision 88):
  - `[Launch plan](../Marketing/Launch%20plan.md)`, relative to the linking
    page, percent-encoded.
  - The text starts as the page's file name, without `.md`.
  - A rename or move inside Bava updates every link's path. Its text changes
    too, but only where it still reads the old name.
- **Heading links** (decisions 44 and 82): `page.md#anchor`, using GitHub's
  anchors (`slug.ts`, as the contents block does).
- **Date chips** (decisions 40 and 87):
  - `@today`, `@tomorrow` or a typed date insert one; a calendar changes it.
  - The readable text is Bava's own format (`2 Oct 2026`) when Bava writes
    it. Hand-written text is kept until the date is changed.
  - A plain typed date never becomes a chip. No reminders.
- **An untouched page saves byte for byte.** Link rewriting touches only a
  link's path and matching text. Nothing inside code blocks, inline code, the
  canvas block, HTML comments or kept blocks is rewritten.
- **The open page is never rewritten on disk.** Its links are updated in the
  editor, as an edit, so its unsaved work and its changed-on-disk stamp stay
  right.
- **IPC surface small** (`.ai/rules/ipc.md`):
  - one new SpaceService method, `Index(root, page)`, returns the Space's
    pages and this page's backlinks;
  - rename and move rewrite links inside the existing `Apply`.
- **No network.** Opening a web link hands it to the system browser, only on
  the user's click (non-negotiable 1: the user triggers it).

### Task 2: Finding and rewriting links (Go, pure)
**Files:** create `internal/space/links.go` and `links_test.go`.
**Behavior:**
- **Finding links:** every inline Markdown link `[text](dest)`, including the
  `<dest>` and titled forms, with the byte ranges of its text and
  destination.
- **What is skipped:** fenced and indented code, inline code spans, HTML
  comments, `<details>` summaries, and the `bava-canvas` block.
- **Resolving:** a destination is resolved against the linking page's folder,
  percent-decoded, with `#anchor` split off. Only `.md` pages inside the
  Space count.
- **Rewriting:** given moves (old path to new path, page or folder prefix),
  each matching destination is written relative to the page's own new place,
  percent-encoded, and its anchor kept. The text is replaced only where it
  equals the old file name. Every other byte is untouched.
- [x] Failing tests, table-driven:
  - links found and skipped in each context;
  - `..` and folder moves;
  - a moved page's own outgoing links;
  - anchors and titles kept;
  - reworded text kept;
  - untouched input returned identical;
  - expected failure: no package
- [x] Implement

### Task 3: The Space's index, and rewriting on rename and move (Go)

- **Failure:** a page that fails to write is reported, never half written.

## As built

- **Forms:** as specified in `docs/file-format.md` ("Links between pages",
  "Date chips"). A date chip in an HTML table cell is read and written too.
- **One set of path rules on both sides:** Go's `internal/space/links.go`
  and the editor's `docs/links.ts` run the same cases,
  `testdata/links/paths.json`, and each was shown to fail when a rule was
  broken.
- **Following links:** a click shows the card; ⌘/Ctrl-click follows. A web
  or mail address goes to the system browser, only then. A link to a file
  that is not a page shows it in the Finder or Explorer. Outside a Space, a
  relative link opens the page beside the file.
- **"Linked from" and missing links** are read again when a page opens, when
  the `@` menu opens, when the window regains focus, and after a rename,
  move, trash or restore, not after every save: only the open page can
  change, and its own save does not change who links to it.
- **Found by the screen checks, fixed:**
  - The calendar never took a pick, and the card's buttons read nothing: the
    pane showed each through `{@const}` of state its own close cleared. Each
    now shows a copy of what it opened for.
  - The calendar's days showed the browser's grey buttons.
  - Renaming from the Files tree's right-click menu failed about 1 time in 2
    in the screen checks (a bug from 8.1, first exercised here): the closing
    menu moved focus into itself a frame later, which ended the rename. The
    rename now starts a frame later; 16 runs of 16 passed.
- **Deviations:**
  - The smoke renames the linked page with F2 in the tree rather than a
    menu, and checks the rewritten link from the reopened page.
  - A jump to a heading on another page has no screenshot: WebKit rounds
    the heading's fraction of a pixel differently from run to run. The walk
    checks where the heading lands instead.
  - Relinking a missing link to its one namesake is covered by unit tests;
    the pretend Space has no page for it, so there is no walk.
- **Spec review: FAIL, then fixed** (each with a test that failed first):
  - Blockers: the hand-written scanner rewrote links in HTML blocks, a
    toggle's summary, text in HTML table cells, indented code after a
    heading or fence or in a list, and fences in quotes and callouts. Where
    a page's prose is now comes from a CommonMark parse (goldmark, MIT,
    already in the build through D2, now a direct dependency and in
    `NOTICE`); inline HTML and inline and block equations are passed over
    too.
  - A link's formatted words no longer follow a rename in the open page (Go
    never changed them); an HTML table link's new words escape `$` and `[`.
  - A failed read of the Space no longer marks every link missing; a folder
    that cannot be read is passed over; stale reads are dropped (`reads.ts`).
  - Saving kept a page's permissions only by accident of the temporary
    file: every save made a page readable by its owner only, a bug older
    than this part. `store.Save` now keeps the file's mode (0644 for a new
    one).
  - From the keyboard: Enter on a selected date chip opens its calendar,
    focus on the chip's day; ⌥Enter in a link opens its card with focus in
    it.
  - A locked page's links show a card with Open only.
  - A date tag with empty words or Markdown's marks stays kept; `?query` is
    kept with the anchor; an address that is not UTF-8 reaches nothing
    (both sides); "Links in 1 page"; a page opened on its own follows `../`
    links; a heading link outside a Space escapes brackets; the `@` menu
    reads the pages without scanning for "Linked from".
  - Left as is: renaming or moving a page rewrites links in locked pages
    too, so they keep working; the calendar stays in English, the app's one
    locale.
- **Second spec review: FAIL, and a change of design** (decision 89, the
  user's choice). The goldmark reader still disagreed with the Document's on
  29 of 113 unusual pages, two of them layouts Bava writes itself. Now one
  reader decides: the Document's markdown-it reader notes where each link
  sits while it reads a page (`pageLinks`), and a rename rewrites closed
  pages from those places in the frontend (`page-links.ts`). Go only lists
  pages with their text (`Index(root, withText)`) and writes back a page
  unchanged since it was read (`Apply` `relink`, `Space.WriteIfUnchanged`);
  its link scanner and goldmark are gone. `testdata/links/pages.json` holds
  68 cases, the review's among them; each must be found, placed, agree with
  what the Document shows, and change nothing but its address.
  - Addresses write `|` as `%7C`, so one never ends a table's cell.
  - Saving: a new file gets what any new file gets (0666 less the umask),
    and a disk that cannot set permissions still saves.
- **Third spec review: FAIL, then fixed.** Three inputs were placed wrongly
  and passed the place check: a reference definition over two quoted lines,
  a pipe-table cell found by searching (inside an earlier cell's code,
  comment or equation), and HTML table anchors found by a pattern (`</A>`,
  `href=` inside a title). Cells are now placed by the row's own split,
  anchors by the table reader's own tags, and a definition only when its
  address is on its first line and reads back as the reference's. Above all, every rewritten page is
  read again with the Document's reader (`onlyLinksChanged`): anything but
  its links' addresses and words changed, and nothing is written; the page
  is named instead. Also: the `changed` refusal code, errors while relinking
  shown, renames and moves one at a time, a temporary file cleaned up on
  Windows even when made read-only.
- **Known, left as is:** a reference link's words (`[Launch plan][p]`) do not
  follow a rename in a closed page, only its definition's address; in the
  open page they do. The words change nothing about where it goes.
- **Fourth spec review: FAIL, then fixed.** A definition written `>b.md`
  (no space after the quote's marker) was still placed on the marker, and a
  CRLF page lost the CR after a definition's address; lint had one error
  that a summary line of the lint output hid. Now a definition is placed
  from its first line only, a span ends just past its last character (a CR
  stays outside), and a byte-level guard sits beside the read-back check:
  each place is written only if what is there reads as the link's own
  address (or words). An address written in `<…>` keeps them.
- **Fifth spec review: PASS.** It fuzzed 240,000 pages over six seeds, with
  names holding every character Markdown treats specially, every link form,
  containers, tables and mixed line endings: no byte changed outside a
  link's address or words, no line ending changed, nothing thrown. Its two
  warnings are fixed: only the first definition of a label is placed (the
  one the page uses), and a failure while relinking is logged as well as
  shown.
