# 05.5: Wiring

**Goal:** Make what already exists usable. Draw on the canvas; open and save a
file. No new capability, only the connections between tested logic and the
window.

**Specs:**
- `.claude/work/plans/04-canvas.md` and `05-persistence.md`: what was built
  and what was left unwired, in their completion records
- `.ai/rules/canvas.md`: the canvas is a plain class; no reactive geometry
- `.ai/rules/design-system.md`: components are presentational
- `docs/file-format.md`: unchanged by this milestone

**File format impact:** none. This milestone writes files through
`internal/format` and `internal/store` exactly as they already write them; it
adds no field and changes no shape.

**UI impact:** `FileTree` added, wrapping Ark's TreeView. `Dialog` reused for
the unsaved-changes and changed-on-disk prompts.

## Why this exists

Milestones 4 and 5 both shipped tested logic with no way to reach it. Selection,
marquee, grouping, paste, dirty tracking, conflict refusal and recents are all
covered by tests and none of them has ever been exercised by a person. Stacking
Milestone 6 on top would widen that gap and push every design problem in the
scene model further from the code that caused it.

## Constraints

- **Nothing new is designed here.** If a behaviour is missing, it is missing;
  it goes to the milestone that owns it, not into this one.
- Every scene change goes through `history.mutate`, so undo stays one history.
- The canvas stays a plain class. Pointer handling lives with it, not in Svelte.
- Components stay presentational: the file tree emits a path, it does not open
  anything.
- Errors the user can act on stay data, not exceptions.

## Completion record, 2026-09-17

185 frontend tests and every Go test green. The app launched (the process ran
and the dev server answered) before the prompts were wired; the prompts are
covered by the App mount test and by `files/actions.test.ts`.

**Task 7 is not done.** Drawing, saving, quitting and reopening by hand needs
someone at the window. Every box under it is unticked.

**The most important bug was found by reading the code, not by a test.** Saving
an untitled drawing called `doc.open` on a path that did not exist yet, which
failed and never set a path, so `doc.save` returned without writing anything.
**A new drawing could not be saved**, the one flow this milestone existed for.
Every earlier test saved a document that had already been opened, which is
exactly why none of them caught it. Fixed with `doc.saveAs`, which does not
open first, and four tests written against the flow that was actually broken.

Reading the same code turned up the two prompts the plan listed and the first
wiring pass left out:

- **Opening another file discarded unsaved changes without a word.** Now it
  asks save, discard or cancel, and if asked to save and the save fails, it
  does not open, since that would lose the work anyway.
- **A save conflict did nothing visible.** The user clicked Save, nothing was
  saved, and nothing said why. Now it asks reload or keep mine.

The policy moved out of markup into `files/actions.svelte.ts` so all three are
tested directly.

**Smaller things the tests caught:** a pen tap produced a zero-size stroke, since
a tap still yields two identical points and the check counted points rather than
distance; and a name collision between the file actions and a template snippet
both called `files`.

**Also replaced:** the canvas repaint was driven by a bare `revision;`
expression read only to subscribe an effect. It now reads a published scene
snapshot, so the dependency is the data itself.
