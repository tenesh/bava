# 05.6: App chrome

**Goal:** Make Bava behave like a desktop app: a native menu bar grouped to
grow, autosave settings, and the brand in place.

**Specs:**
- `.claude/plan/roadmap.md`
- `.ai/rules/wails.md`: the native surface stays thin
- `.ai/rules/design-system.md`, `docs/shortcuts.md`
- `internal/config`: the settings file from Milestone 5
- `~/Workspace/designs/bava/claude-design-logo-v1`: brand sheet. **Reference

## Constraints

- **The menu is data.** One declarative spec defines every item (id, label,
  accelerator, kind, platform), shared by Go and the frontend tests. Adding a
  later item is adding a spec entry and a handler, not touching the wiring.
- **One command path.** A menu click emits `menu:command` with the item's id;
  the frontend has one dispatcher. The frontend reports state back (dirty,
  view mode, theme, selection, undo availability, recents), and Go updates
  checks, enabled state and the Open Recent submenu.
- **No single-letter accelerators on native menu items.** A native accelerator
  is captured before the webview sees the key, so binding `R` would make it
  impossible to type an R. Tool letters appear in the label only; the canvas
  keymap keeps handling them.
- **Reserved for prose editing in Milestone 8:** `⌘B`, `⌘I`, `⌘U`, `⌘K`,
  `⇧⌘X`. No menu item may take them now, or Milestone 8 has to break an
  existing shortcut.
- **Every accelerator is unique and appears in `docs/shortcuts.md`**, enforced
  by a test against the spec.
- **Menu and keymap never both fire.** Anything bound on the native menu is
  removed from the JS keymap.
- **Autosave never overwrites a file another program changed**, and never
  interrupts typing with a dialog.
- **Autosave never touches an untitled document.** It has nowhere to write.

### Decisions taken in this plan

- **Native About on macOS**, via Wails' `ShowAbout`, which uses the app icon and
  name. A custom About window rendering `NOTICE` remains Milestone 16.
- **Autosave defaults to off**, matching VS Code. Modes: `off`, `afterDelay`
  (default delay 1000ms), `onFocusChange`.
- **A conflict pauses autosave rather than prompting.** The status bar says why;
  the next manual Save raises the existing conflict prompt.
- **`Canvas`, not `Arrange`,** as the menu name: it matches the view mode and
  has room for Insert later.

## Status, 2026-09-17

Tasks 2–8 done and gated. Task 1 needs a human at a running window. Task 9 moved
to Milestone 5.7, blocked on the SVG art.

**What changed from this plan after the spec review** (the code is the record):

- Cut, Copy and Paste are commands routed by focus, not native roles; the roles
  never reach a canvas on Windows or Linux. Task 1's question is therefore
  narrower: whether each command fires at a window, not which mechanism to use.
- Punctuation shortcuts (`⌘,` `⌘=` `⌘-` `⌘/` `⇧⌘[` `⇧⌘]`) are spec `shortcut`
  entries matched by the page; Windows never fires them as accelerators.
- Not built: menu state for dirty and undo availability, Clear Recent, and the
  native About panel on macOS (About is an in-app dialog). All deferred, none
  blocking.
