# 08.1a: Testing layers

**Goal:** Bava is checked by looking at it, not only by logic tests: every
screen is rendered in a real browser engine and compared with approved
screenshots, and the real app runs a smoke walk on Linux, macOS and Windows,
so the user no longer tests by hand after every change.

**Specs:** the discussion of 2026-09-27 (layers 1, 2 and 3; screenshots kept
in the repo, on the same branch, organised); `.ai/rules/testing.md`;
`CLAUDE.md` (non-negotiables 1 and 2, Testing); Wails v3's testing and e2e
guides (bindings do not work in a plain browser; mock them).
**File format impact:** none.
**UI impact:** none to the app. Test-only code never reaches a release build.

## Constraints

- **Three layers.** 1: the existing logic tests (`go test`, `vitest`),
  unchanged. 2: **screen checks**: the interface in a real WebKit browser, the
  Go side replaced by a stand-in over an in-memory Space, screenshots compared
  with approved references. 3: **smoke runs** of the real app binary on
  Linux, macOS and Windows in CI, walking a few key flows and saving
  screenshots.
- **Screenshots live in the repo, on `main`, organised:**
  `testdata/visual/<area>/<screen>--<state>--<theme>.png` for layer 2
  references (areas: `shell`, `space`, `dialogs`, `settings`, `canvas`,
  `start`). Layer 3 screenshots are CI downloads, never committed.
  Kept small: each image cropped to its screen or dialog, never the full
  desktop, at 1× scale.
- **Kept out of releases:** the app embeds only `frontend/dist`, which never
  imports test code; layer 3's driver sits behind a Go build tag `e2e` that
  release builds never set, and a test proves a default build lacks it.
  `.gitattributes` marks `testdata/visual/` `export-ignore`, so source
  archives leave it out.
- **Deterministic references:** layer 2 runs in a pinned container image
  (the test browser's official Linux image, arm64 locally, the same on CI's
  `ubuntu-24.04-arm` runner), with animations off, fonts bundled, a fixed
  window size and a fixed clock. The same command runs locally and in CI.
- **A reference changes only when looked at.** Updating references is an
  explicit command; the report lists every changed image, and each is opened
  and read before it is kept, as for D2 goldens.
- **No network beyond the one-time tool install** the user approves; tests
  make no network calls. Test scratch folders live under the container's or
  runner's temp; nothing touches the user's files.
- **Where each layer runs.** On the user's Mac: layer 1 directly, layer 2 in
  its container. On GitHub CI: all three, layer 3 only there (Linux, macOS
  and Windows runners), after the user pushes. Nothing ever drives the
  user's screen.
- **Layout.** How tests run lives in `tests/`: `tests/docker/visual.Dockerfile`,
  `tests/scripts/visual.sh`,
  `tests/e2e/scenarios/*.json`. Test code stays beside what it tests:
  `frontend/tests/visual/` (harness and specs), `internal/e2e/`,
  `frontend/src/e2e/driver.ts`. Expected results live in `testdata/`
  (`testdata/visual/`, beside `testdata/golden/`). `docs/testing.md` opens
  with this map.

### Task 2: The stand-in Go side (layer 2)
**Files:** create `frontend/tests/visual/harness/fake-services.ts` (SpaceService,

**Behavior:** the fakes answer as the Go services do, including error codes

empty Trash). A test pins that each fake method exists on the real binding

### Task 4: The smoke driver in the real app (layer 3)

## Out of scope
Running layer 3 on the user's Mac: no local Linux container for it, and no
local macOS or Windows virtual machines (containers can only run Linux; CI
runs all three the same way); a hosted screenshot service; git
large-file storage (screenshots stay small and in the normal tree, as the
user chose).

## As built (2026-09-27)

**Layer 2 works end to end.** 54 walks (27 screens, each in light and dark)
run in the pinned container in about 13 seconds and produce 52 references
(1.5 MB) under `testdata/visual/<area>/`. A second run with no update passes,
so the pictures are deterministic. Removing the global `[hidden]` rule made
every walk fail, so the layer catches the bug that motivated it.

*Since:* layer 3 runs on CI. It first went green on all three platforms at
`9cf4d06`, after `f4c2d5f` and `9cf4d06` fixed what its first runs found.

**Layer 3 is built but has not run yet.** The driver, scenarios and CI jobs
exist and their logic is tested (`internal/e2e`, `src/e2e/driver.test.ts`,
`release_test.go`, and a normal frontend build checked to contain no driver),
but the real app has only ever run it on CI, which needs a push. Expect the
first run to need adjusting: the macOS screen-recording grant and Windows
screenshots in particular are unproven.

**What looking found, and what was done about it:**
- Fixed: the title said "untitled saved" with a Space open and no page; the
  status bar's Nodes counted D2 nodes instead of canvas elements; dialogs
  opened on a button (the Trash on Empty Trash) instead of their first field;
  Settings rows touched; the Shortcuts' Canvas group ran headless into a third
  column (submenus are now their own groups, "Canvas: Tools"); the new-row
  field drew a double border; the Export preview was clipped; the source
  editor kept CodeMirror's light gutter and current line in dark.
- Decided by the user: a picked colour shows as picked in light and inverted
  in dark, as in Excalidraw, replacing the rule that flipped pale fills to
  near-black in light (`docs/decisions.md`, `docs/file-format.md`).
- Left for 8.2: the Document pane never shows or saves a page's text; it has
  been a scratch D2 editor since the shell was built. 8.2 replaces it.
- Left, small: the "No page open" hints say "New file" for ⌘N, which makes a
  page in a Space; the first tree row shows a focus ring after a Space opens.

**Deviations from the plan.** Screenshots in layer 3 are taken by
`internal/e2e/capture.go`, not scripts. `internal/e2e` is an ordinary package
linked only through `main_e2e.go` (`//go:build e2e`), not tagged itself; the
release test proves a normal build does not link it. The page side calls Go
by name, so no generated binding exists for it in any build. The local Linux
container for layer 3 was dropped at the user's request.
