# 08.3a: Blocks inside a page

**Goal:** the Document gains callouts, toggles, code blocks, equations,
footnotes, a contents block and emoji. Each is editable in the page and
saved as Markdown that other apps read.

**Specs:** `.claude/work/specs/08-documents.md` decisions 13, 14, 19, 22, 23,
38 (emoji), 42, 43, 51, 76, and 77 to 82 (settled for this plan);
`docs/file-format.md` ("The document"); `.ai/rules/editors.md`,
`.ai/rules/file-format.md`, `.ai/rules/design-system.md`; the Bava Design
mockups' Document and Menus boards.
**File format impact:** yes, specified first in `docs/file-format.md`
(Task 1). Callouts, custom callouts, toggle lists, toggle headings, code
blocks with wrap and caption, equations, footnotes and the contents block
stop being kept read-only and become blocks Bava reads and writes.
**UI impact:**
- **New blocks:** callout, toggle list, toggle heading, code block, equation,
  footnote and contents, each drawn by the editor. The `/` menu gains these
  blocks and Emoji.
- **New components:** `EmojiPicker` (search and grid, wrapping Ark's Popover)
  and `EquationField` (edit an equation's TeX with a live preview, sharing
  `.bava-field`).
- **New tokens:** callout colours from the swatches, and the code block and
  equation spacing.

## Constraints

- **Nothing is lost** (non-negotiable 2). Everything 8.2 keeps byte for byte
  that this part does not take over stays kept. Tables stay kept until 8.3b.
- **An untouched page saves exactly as read**, as since 8.2. Every new form
  gets a round-trip test and joins the "keeps what it shows" check.
- **Callouts** (decisions 13, 78):
  - Written as `> [!info]`, `> [!note]`, `> [!success]`, `> [!warning]` or
    `> [!error]`.
  - A custom callout is `> [!note]` with the mark
    `<!-- bava: color=<swatch> icon=<emoji> -->` above it.
  - The text after the marker on its first line (an Obsidian title) and a
    fold sign (`-` or `+`) are kept as written.
- **Toggle lists** (decisions 14, 80): written as
  `<details>`, `<summary>…</summary>`, the content, then `</details>`, one
  blank line between each part.
- **Toggle headings** (decision 79): an ordinary heading with the mark
  `<!-- bava: toggle -->` above it.
- **Folding** (decision 80): never written to the file and never marks the
  page unsaved. It is remembered on this computer, per page, inside
  try/catch. A toggle with no memory starts folded; `<details open>` in the
  file starts open and keeps its `open`.
- **Code blocks** (decisions 19, 81):
  - A fence with the language: `` ```go ``.
  - Wrap and caption go in the mark `<!-- bava: wrap caption="…" -->` above
    the fence.
  - Highlighted with the canvas code blocks' own language list and colours
    (`canvas/code/languages.ts`, `highlight.ts`), loaded when first used.
  - The code is ProseMirror text with highlight decorations, not a
    CodeMirror editor inside the page, so there is one undo history and no
    focus hand-off. (`.ai/rules/editors.md` describes an embedded CodeMirror
    for diagram blocks, which were never built; this part updates that rule.)
  - A `d2` fence is an ordinary code block with the `d2` language.
- **Equations** (decision 23):
  - `$$…$$` as a block and `$…$` inline, drawn with KaTeX (MIT), bundled.
  - Edited in `EquationField`. A formula that does not parse shows its TeX
    and the error, never a blank.
  - KaTeX's fonts are bundled, with their licence checked and entered in
    `NOTICE`.
- **Footnotes** (decision 42):
  - A reference is `[^label]` and its note is `[^label]: …`.
  - A reference shows a number counted in reading order.
  - Notes are written after the page's last block, in reference order, with
    their labels kept.
  - A new footnote takes the next free number as its label.
- **Contents** (decision 82):
  - The list of heading links goes between `<!-- bava: contents -->` and
    `<!-- bava: /contents -->`, rewritten on every save.
  - Anchors follow GitHub's heading slugs (lower case, spaces to `-`,
    punctuation dropped, `-1`, `-2` for repeats).
  - The list read from the file is discarded and rebuilt from the headings.
    That is its one change on save, and only when a heading changed.
- **Emoji** (decision 38):
  - Saved as the character itself.
  - Typing `:` and two letters of a name offers matches, as the `/` menu does.
  - The `/` menu's Emoji item opens `EmojiPicker`, which a custom callout's
    icon also uses.
  - Names come from `unicode-emoji-json` (MIT), loaded on first use.
  - Emoji are drawn by the system's emoji font. Bava bundles no emoji font:
    a colour emoji font costs about 10 MB. Flagged under "Deviations to
    confirm".
- **Libraries:** `katex` and `unicode-emoji-json`, pinned exactly; `NOTICE`
  entries in the same change.
- **Tests:** every file-format rule has a round-trip test; every command
  with logic has a unit test; every new block has a screen walk in both
  themes; the smoke scenario adds a code block and an equation, and finds
  them after reopening.

## Deviations, confirmed by the user (2026-09-27)
- **Emoji font:** emoji use the system's emoji font, not a bundled one. The
  other fonts are bundled so every platform matches; a colour emoji font
  adds about 10 MB.
- **Code in the page is not a CodeMirror editor.** It is highlighted by the
  same parsers and colours but edited as page text. The result is one undo
  and no focus traps, at the cost of CodeMirror's own editing keys
  (multiple cursors, bracket matching).
- **Callout titles:** a title written in the file (Obsidian's
  `> [!info] Title`) is kept and shown in bold, but not edited in this part.

## As built

- **Format:**
  - Every form is specified in `docs/file-format.md`.
  - The contents block writes a blank line on each side of its list, because
    markdown-it otherwise takes the closing mark into the list's last item.
  - A toggle's summary is plain text, because formatting inside `<summary>`
    shows as raw marks on GitHub.
  - Code fences lengthen past any run of backticks in the code, so the repo's
    own `docs/file-format.md` example, which nested fences wrongly, now reads
    correctly (fixed in the doc too).
  - The real-Markdown test now checks that every repo page shows the same
    after a save, instead of checking each fence byte for byte.
- **Footnote notes** are written in the order their references are first
  read, and read back that way; a new note is added to the foot and sorted on
  save.
- **Emoji** are listed up to Unicode's emoji 14.0. Newer ones showed as empty
  boxes in the screen checks' Linux font.
- **Found by the screen checks and fixed:**
  - a toggle heading's arrow sat under the block handle and could not be
    clicked;
  - saving an equation, and picking an emoji, threw: a `{@const}` read after
    the state it follows was cleared (now a rule in `.ai/rules/editors.md`);
  - a folded toggle's arrow first drew as open;
  - a footnote's ↩ sat on its own line.
- **Fixed in the walks, not the app:** the helper that puts the caret at a
  page's end now places it directly. After a click, the editor settles the
  click's own caret a moment later, and End or a direct placement made in
  that moment was overwritten.
- **Deviations** (from the plan):
  - Headings inside callouts and toggles are listed in the contents too,
    since GitHub numbers anchors across every heading.
  - The custom callout's default is gray with 💡.
- **Smoke:** the scenarios add an inline equation and a Go code block and
  find both after reopening; they need a push to run.
- **Spec review: FAIL, then fixed.** It ran about 250 adversarial round trips
  and found seven blockers, each now covered by a test that failed first:
  - a callout whose first block was a divider, a coloured paragraph, a
    toggle heading, a toggle or a table lost it (a `>` line now separates
    any first block that is not plain text);
  - a callout title line running into the body (a code span, a link, bold)
    dropped words (the body is now read again on its own);
  - inline TeX ending in or holding backslashes or `$` turned into text
    (the reader skips escaped dollars; TeX edited in Bava is kept on one line
    with `$` escaped; the typing rule skips an escaped close);
  - a tight list with a code block in an item changed on every save (a tight
    item's blocks now follow each other directly, or the list is written
    loose);
  - a `~~~` fence with a backtick in its opening line was destroyed (written
    with tildes);
  - a table or `</details>` straight after a paragraph was read as its text.
    This predates 8.3a: markdown-it's `Ruler.at` resets what a rule can
    interrupt, and the wrappers now pass it back;
  - backslashes were stripped from toggle summaries (entities only decode
    now, through `entities`, pinned to markdown-it's own 4.5.0 so there is
    one copy).
- **Warnings fixed:**
  - icons that could end a mark are quoted;
  - a footnote reference before a `:` at a line's start escapes the colon;
  - anything but a list between the contents marks is kept;
  - a line of `$$` in block TeX is escaped;
  - inline `$$…$$` is kept as written;
  - fence info and callout titles keep their own spacing;
  - the format doc covers indented and empty code blocks;
  - a failed emoji load is retried;
  - fold memory is written only when a fold changes;
  - the `1em` literal became a token;
  - an inline equation's field says Enter saves, and Shift+Enter saves too.
- **Footnotes moved by cut and paste keep their note** (the user's choice
  after review): a note whose last reference is deleted stays in the editor
  and is left out only when the page is saved, so a pasted reference finds
  it again.
- **Warnings kept:**
  - The canvas and shell references changed only because the seeded Space
    gained `Engineering/Blocks.md`, which shows in the Files tree.
