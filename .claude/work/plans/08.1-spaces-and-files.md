# 08.1: Spaces and files

**Goal:** Open a folder as a Space and organise its pages in a Files tree
(folders, order by hand, duplicate, Bava's own Trash), with a start screen,
a Space switcher and Space settings; a single page still opens on its own.

**Specs:**
- `.claude/work/specs/08-documents.md`, decisions 2 to 10, 45, 46, 52, 53,
  55 to 57, 63 to 65, 67, 69 to 71 (the Trash never empties itself;
  Templates, Tags and Media wait for 8.4 and 8.6).
- Mockups (reference, not spec): Bava Design,
  https://claude.ai/artifact/RMvLeKBkbF4N2Hv89HSude: Start screen, Space
  open, Space switcher and settings, Trash dialog, Settings, States.
- `docs/file-format.md` ("Why one file rather than a sidecar", reworded
  here), `docs/ipc.md`, `docs/shortcuts.md`, `docs/decisions.md`
- `.ai/rules/file-format.md`, `ipc.md`, `wails.md`, `svelte.md`,
  `design-system.md`

**File format impact** (specified first, with round-trip tests):
- **A Space** is a folder with a `.bava/` folder inside it. Opening a folder
  as a Space creates `.bava/space.json` when it is missing.
- **`.bava/space.json`**, version 1: `order` (per folder, relative to the
  Space, the names of its pages and folders in the order the user arranged
  them; a name not listed goes at the end, sorted by name; a listed name
  that no longer exists is dropped on the next write) and `pageWidth`
  (`narrow`, `wide` or `full`; absent is the user's app setting). Unknown
  keys survive a save.
- **`.bava/trash/`**: each deleted page or folder moved, whole, into
  `.bava/trash/<id>/`, with `item.json` beside it (`path` it came from,
  `deletedAt`, `kind`). Kept until the user deletes it or empties the Trash.
- **Reworded:** "Why one file rather than a sidecar" says what `.bava`
  holds (Space data, never a page's text or canvas) and states the
  attachments trade-off decision 10 accepted (8.4 builds attachments).
- Pages themselves do not change.

**UI impact:**
- **New components:** `SpaceTree` (rows, expand and collapse, inline
  rename, drag to move and reorder with a drop line, unsaved dot),
  `SpaceSwitcher` (Ark Menu), `StartScreen`, `TrashDialog`,
  `SpaceSettingsDialog`.
- **Changed components:** `SettingsDialog` gets a section list on the left
  (Appearance, Files, Canvas, Advanced). `FileTree` is retired.
- **New tokens:** `--size-tree-indent` (14px) and `--size-tree-drop-line`
  (2px) as planned; the restyle after it added many more (see As built).

## Constraints
- **The tree:**
  - It shows folders and `.md` pages only: no `.d2` files, no hidden
    entries, never `.bava` (decisions 10, 69).
  - The order comes from `space.json`, ordered by hand, and new items go at
    the end (decision 9).
- **Files stay the truth:**
  - Every operation is a real file operation in Go, through one service;
    Bava never keeps a second copy of the tree.
  - Paths from the frontend are relative to the Space. One that leaves the
    Space, names `.bava`, or holds `..` is refused.
- **Trash:**
  - Deleting moves into `.bava/trash`. Nothing is removed for good except
    by Delete in the Trash or Empty Trash, each confirmed (decision 70).
  - Restoring recreates missing folders; a name clash is saved numbered
    ("Launch plan 2") (decision 69).
- **New pages and duplicates:**
  - A new page is named in the tree first, then opened (decision 69).
  - ⌘N makes it beside the open page (decision 71).
  - Duplicate makes "Name 2" beside the original.
- **Saving** stays ⌘S with optional autosave. Leaving a page with unsaved
  changes asks, naming the page (decisions 57, 64).
- **Per-viewer conveniences** stay in `localStorage` inside try/catch
  (`CLAUDE.md`): recent Spaces and files, the last Space and its last page,
  and expanded folders. Work data lives in `space.json`.
- **External changes** (Finder, sync): the tree is refreshed when the window
  regains focus and after every operation. No file watcher in 8.1.
- **UI components are presentational:** no IPC in `components/`.
- **Svelte 5 runes only;** Ark UI wrapped; tokens only.

`npm run lint`, `npm test` (exit 0, 1568 passed, 1 skipped), `go vet` and
`go test ./internal/... .`.

**Test-first record.** The boxes are ticked because the work is done, not
because every test came first:

- Tasks 1 to 3 (Go): tests first. File times show each `_test.go` written
  before its code.
- Tasks 4 to 9 (frontend): the first build wrote several tests after the
  code. The review caught it: `space-tree.test.ts` was written ten minutes
  after `SpaceTree.svelte`, and `tree.ts` and its test in the same second.
  The review fixes below were done test-first: each new test was run red,
  then made green. The tests added afterwards for behaviour that already
  existed (naming a new row, cancel, submit, drag, New Page showing the Files
  pane) were each checked by breaking the code and watching them fail. Two
  can't be caught that way: the rename-cancel test, because Escape never
  reaches the submit path, and the drop-refusal test, which rests on
  `dropTarget`'s own tests.

**Spec review: FAIL, then fixed.** One blocker and twenty warnings, all
checked against the code and all real:

1. and 12. A rename differing only in case could overwrite another file
   (and so could renaming a Space). `replaces` now asks `os.SameFile`. The
   case-sensitive test skips on macOS, where the filesystem ignores case.
2. Spaces fell off recents when pages were opened: each kind now keeps its
   own ten.
3. "Open its folder as a Space" closed the loose page: it now stays open as
   the Space's page.
4. New Page and New Folder did nothing visible with the Files pane hidden:
   they show it first.
5. A refused new name left the row stuck: it gets a fresh row to name again.
6. `refresh` blanked the tree and had no staleness guard: it builds the tree
   aside, shows it once, and drops an older listing.
7. A move raced autosave: `autosave.settle()` runs first, and the open page
   follows its file before the tree is re-read (`apply`'s `before`).
8. Duplicate copied from disk and lost unsaved edits: the page is saved
   first.
9. Renaming a Space re-read the old root, lost the open folders, and left
   recents stale: no refresh on the old root, `carryTo`, `recents.renamePrefix`.
10. The service trusted `root`: every method loads the Space through
    `space.Load`.
11. Symlinks were followed: `resolve` refuses a path through one.
13. A failed trash left an empty slot: it is removed unless the move
    happened.
14. Trashing a folder loses its inner order: documented in
    `docs/file-format.md` rather than changed.
15. Hardcoded strings: the placeholder names, error text, size units and the
    folder picker's title go through `t()`.
16. The Space tile borrowed canvas swatches: first given its own
    `--color-space-tile-*` tokens; the restyle later gave each Space its
    own swatch colour on purpose (`components/space-tile.ts`), and those
    tokens were removed.
17. Literals: `--size-menu-gutter`, read by the positioner at run time, and
    `--size-dialog-list-max`.
18. `SectionTabs` reached into the sections' margins: the margin is gone at
    the source.
19. Missing tests: added (see above), with `spaceChoices` and `unsavedBody`
    pulled out of `App.svelte` so they can be tested on data.
20. Order had no tiebreak: the raw name breaks ties.
21. A moved folder collapsed: `space.followMove` keeps it open.

**Second review: FAIL, then fixed.** It confirmed all 21 fixes. It also
found one blocker, the staged `git rm --cached` below, which only the user can
undo, and six warnings, each fixed test-first:

1. A folder closed during a refresh reopened: `refresh` reads again when the
   open folders changed while it was reading.
2. and 3. `settle()` stopped only the save already queued, so an edit made
   during a move or a Space rename could still write to the old path.
   `autosave.hold()` now writes nothing until it is released. The Space rename
   moves the page as soon as the rename succeeds, before reopening the Space.
4. Go's refusals reached the user in English: they carry a `code`
   (`internal/space/errors.go`), worded by `spaceMessage` through
   `space.error.*` keys. File system errors still show as they came.
5. Recents kept renamed, moved and trashed pages: `relocate` calls
   `renamePrefix`, and `trashPath` calls the new `removePrefix`.
6. `Restore` followed a folder that had become a link: it resolves the path
   like every other operation.
