# 08.5: Canvas in the Document

**Goal:** a page can embed any frame of its Space's canvases as a picture
Bava keeps up to date, made from either side, opened on the canvas with a
click, and Diagram from Code can start from the page.
**Specs:** `.claude/work/specs/08-documents.md` decisions 24 to 27, 52, 61
and 64; `.claude/work/specs/08.5-canvas-in-the-document.md` decisions 1 to
6 (2026-10-04); `docs/file-format.md` (Invisible marks, Images and videos,
Links between pages, `.bava/attachments/`, Attachment and containment);
`docs/ipc.md`; `.claude/plan/roadmap.md` Milestone 8 exit criterion.
**File format impact:** a new block, the canvas embed: an image of the
frame's picture with an `embed` mark (below). No change to the canvas
block. Pictures are PNG files in `.bava/attachments/`.
**UI impact:** one component added, `FramePicker` (the `/` Embed frame
list, frames by name with thumbnails, grouped by page). The media block's
menu, `ConfirmDialog` (loose page) and `DiagramDialog` reused. Strings in
`messages.ts`; tokens added as built: `--opacity-gone` and four `--size-frame-*`.

## The file form

```markdown
<!-- bava: embed=f3 width=large caption="The write path" -->
![Ingest pipeline](.bava/attachments/Architecture - Ingest pipeline.png)

<!-- bava: embed=f7 page="../Engineering/Architecture.md" -->
![Write path](.bava/attachments/Architecture - Write path.png)
```

- **`embed=<id>`**: the frame's element id on its page's canvas.
- **`page="<address>"`**: the page whose canvas holds the frame, written as
  a link's address is (relative to this page, encoded the same way), left
  out when it is this page. Moving or renaming that page in Bava rewrites
  it, as it rewrites links.
- **The image**: the frame's picture in the attachments, an ordinary
  Markdown image, so every other app shows the picture. Alt text starts as
  the frame's label; Bava keeps what is written there.
- **Settings**: `width`, `align` and `caption` as an image's; no `ratio`.
- **The picture's name** is made once, when the frame is first embedded:
  `<page name> - <frame label>.png` (`<page name> - Frame.png` for a frame
  with no label), numbered if the name is taken; it is never renamed by
  itself. Every embed of the same frame uses the same picture.
- **When the picture is written**: when the page holding the frame is saved,
  every picture of its frames that any page in the Space embeds is drawn
  again (PNG, twice size, everything over the frame's area without its
  border or label, on the canvas background, in the theme Bava has then) and written only if its
  bytes changed. An embed made from another page draws the picture from
  that page's file at once.
- **A frame that is gone**: the embed keeps its picture and shows "frame
  deleted"; the picture stays in attachments while any page names it (the
  Media rule as it is). Undo on the canvas brings the frame back, and the
  embed goes live again.

## Constraints

- No editor inside the Document: clicking an embed opens the canvas
  (decision 24). In the Document view it switches to Both (decision 6).
- One page open at a time (decision 64): an embed of this page's frame is
  drawn live from the scene in the current theme; an embed of another
  page's frame shows its picture file.
- A loose page asks to become a Space before it embeds (decision 5),
  through the flow images already use.
- Bindings resolve through element ids, never coordinates (CLAUDE.md).
- The canvas stays outside Svelte reactivity: the live picture is drawn by
  the canvas's own export code (`canvas/export/`), never by a Svelte
  component per element.
- Strings in `messages.ts`; tokens only; Ark wrapped; the media menu reused.
- Debounce the live redraw as the canvas's other derived work: 250ms after
  the scene stops changing.

## Out of scope

- Zoom to fit or zoom to selection (Milestone 15); opening pans only.
- Export of pages with embeds (Milestone 15: embeds are already pictures).
- Embeds of anything but a frame; editing inside the Document; synced
  blocks (decisions 26 and 28).
- Rewriting pictures of a page changed outside Bava: they are drawn again
  the next time Bava saves that page.

## As built

A page embeds any frame of its Space's canvases: `/` Embed frame (the
picker), a frame's right-click Embed in Document, and `/` Diagram from code,
which puts the diagram in a new frame labelled "Diagram" below the canvas's
content and embeds it. This page's frames are drawn live and redrawn 250ms
after the canvas or theme changes; another page's show their picture file.
A click opens the frame's page if needed, shows Both, selects the frame and
centres it when it is out of view. Saving a page redraws, in the theme of
the moment, every picture any page embeds of its frames.

**Checks:** `npm test` 2,668 passed and 1 skipped (204 files); `npm run
browser` 425 passed (204 visual, 221 integration) after the review's fixes,
424 in three full runs before; 248
references, six rewritten and read in both themes (the pickers sheet, the

**Deviations**

- **Right-click on a frame.** It only found a frame on its outline, while a
  left click takes it anywhere inside, so right-clicking inside a frame
  cleared the selection and Embed in Document was out of reach.
  `rightClickHit` (`canvas/context-menu.ts`) now falls back to the innermost
  unlocked frame under the pointer.
- **An embed's page is resolved from this page.** The view first passed the
  mark's written address (relative, encoded) to the frame check and to
  opening, so a frame that existed showed "Frame deleted" (the Document's
  media sheet showed it). It now resolves the address against this page.
- **Embed and diagram logic sit in `files/embed-actions.ts`** with injected
  reading, drawing and writing, so Tasks 7 and 8 are unit-tested away from
  `App.svelte`; App wires it.
- **Saving does not redraw twice for nothing:** a save with the same scene
  and theme as the last redraw of that page skips it.
- **Another page's code blocks** are coloured by a code-runs store of their
  own when that page's frame is drawn.
- **A fixture page has a frame** (`Release checklist`, "Release flow"), so
  the Document's sheets show an embed from another page at rest and one
  whose frame is gone.
- **`Operation`'s pinned JSON keys** gained `replace`
  (`internal/app/json_test.go`).
- **`SavePicture(name, data, replace)`**: the first picture takes a free
  name, a redraw writes its own name; the plan had no `replace`.
- **Tokens:** `--opacity-gone` for a gone frame's picture, and four
  `--size-frame-*` for the picker, where the plan said none.
- **FramePicker is on the pickers sheet**, not menus; the embed states are
  on the Document's sheets (`fixtures/document-blocks.ts`), not a new test
  in `visual/document.spec.ts`.
- **An embed's block menu has Open on canvas**, so its frame opens by
  keyboard (⌘/) as well as by a click.

**Review:** the spec-reviewer's blocker (no browser run in its evidence) was
already met: three full runs, every changed picture read in both themes.
Fixed from its warnings: the file-format example's address from a folder,
a misplaced doc comment, the Go error's context, a late drawing after an
embed is gone (now dropped and freed), a failed embed or redraw now said
and logged, the untitled picture name made a named constant, the debounce
test read from its constant, Open on canvas for the keyboard, and an
integration test for redrawing in a new theme (shown to fail without the
theme check). Left as is: the reader accepts an attachments address at any
depth; `embedsIn` is where a picture is checked against the Space's
attachments.

**Left to a person at a running window:** an embed's live redraw while
drawing beside it (feel), a theme change redrawing embeds, the picker by
keyboard in both themes, clicking an embed from the Document view on each
platform's webview, and the end-to-end `canvas` walk's new steps on CI.

**Fixed after use (2026-10-10):** the picture drew only the frame's members,
so a frame drawn around shapes already there came out empty, and a shape
over its edge was left out. It now draws everything over the frame's area,
cut at its edges (decision 3, settled further with the user). The page also
showed the picture at its pixel size, twice the frame's; it now shows it at
the frame's own size unless a width is chosen.
