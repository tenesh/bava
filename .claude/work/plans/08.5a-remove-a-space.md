# 08.5a: Remove a Space from the list

**Goal:** a Space can be taken off Bava's list of Spaces from the app, its
folder untouched unless the user also deletes its `.bava` data.
**Specs:** the user's request (2026-10-06): "We need a way to remove a space
from the app UI", with the placement chosen the same day: the start screen's
Recent rows and the Space switcher. `docs/decisions.md` (recent Spaces are a
per-viewer convenience in local storage); `.ai/rules/design-system.md`
(StartScreen, SpaceSwitcher).
**File format impact:** none to the format. Removing can delete a Space's
`.bava` folder when the user ticks it (decision below).
**Decision (2026-10-06, the user):** removing asks each time. The
confirmation has an unticked switch, "Also delete Bava's data in this
folder", saying what goes (the pages' images and files, the Trash, page
order) and that it cannot be undone; the pages stay. Deletion is permanent:
Bava has no system-Trash support.
**UI impact:** StartScreen gains a remove button per Recent row;
SpaceSwitcher gains "Remove from List". No new component. Strings in
`messages.ts`. No new tokens expected; any needed is added first.

## Constraints

- Removing asks first. Unless the switch is ticked it touches nothing on
  disk, and opening the folder again brings the Space back.
- Deleting removes `<Space>/.bava` only, never a page; it refuses a `.bava`
  that is a link, so nothing outside the Space can go. A missing folder's
  row offers no switch.
- Removing a Space forgets everything under it too (pages opened from it),
  as a Space sent to the Trash does (`recents.removePrefix`).
- The Space Bava reopens at launch (`bava.lastSpace`) is forgotten when it
  is the one removed.
- Components stay presentational: they report a path; App forgets it.
- Storage reads and writes stay inside try/catch, as they are.

## Out of scope

- Deleting a Space's folder from Bava (its `.bava` data is in scope, above).
- A native menu entry for it.

## As built

A recent Space comes off the list from the start screen (a × after each
row) or, for the open Space, from the switcher's Remove from List. Both ask
first; the confirmation's switch, off at first, also deletes the Space's
`.bava` folder for good. The open Space is closed first (an unsaved page is
asked about, and Cancel stops it); the Space and everything under it leave
the list, and Bava stops reopening it at launch.
