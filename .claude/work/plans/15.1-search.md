# 15.1: Search across a Space, and find on the Canvas

**Goal:** ⇧⌘F opens a palette that finds pages and folders by their names,
their Document and their Canvas, and opens each result at its match; ⌘F
finds on the Canvas as it does in a page.
**Specs:** `.claude/work/specs/search.md` decisions 1 to 13 (2026-10-11);
`.claude/work/specs/documents.md` decisions 44 (find in a page) and 58;
`.claude/work/specs/look.md` (the look); `docs/ipc.md`; `docs/shortcuts.md`;
`.ai/rules/design-system.md`, `ipc.md`, `canvas.md`, `editors.md`,
`testing.md`.
**File format impact:** none. Search reads pages; it writes nothing.
**UI impact:** one component added, `SearchPalette` (a field and its
results at the top centre of the window, over a backdrop); `FindBar` gains
an initial query and a find-only form; `SpaceTree` gains a row to reveal;
the canvas stage outlines find matches. Tokens added if needed (the
palette's width and top offset). Strings in `messages.ts`.

## Constraints

- **From the spec:** a palette at the top centre (3); ⇧⌘F / Ctrl+Shift+F,
  also File ▸ Search, ⌘K stays Link (5); names, page text and canvas text
  (2) of the Space's pages and folders only: no templates, no Trash,
  nothing under `.bava` (11); every word typed must appear somewhere in the
  page, capitals ignored, a word matching the start of longer words (6);
  one row per page or folder, its name and folder, its best match beneath
  with the search words marked, the number of matches at the end (4); only
  a hint before anything is typed: "Search pages, folders and canvases"
  (10); a Document match opens the page scrolled to it with the find bar
  filled with the matched word (8); a canvas match opens the Canvas (Both
  when the Document shows) with the element selected and in view and the
  Canvas's find bar filled (7, 9); a folder opens in the Files tree,
  unfolded and in view, the side pane shown (13); a loose page offers to
  become a Space (12).
- **Find on the Canvas (9):** ⌘F on the Canvas opens the same bar: every
  element whose text matches is outlined, the current one selected and
  panned into view; Enter and ⇧Enter step; Esc closes. Find only.
- **IPC:** errors are data with a `code`; the root is checked on every call;
  paths relative with `/`. Typing debounces 250ms and every request carries
  an incrementing id, stale answers dropped (CLAUDE.md, `ipc.md`).
- **No service of ours.** Search reads the Space's files on this machine;
  nothing is sent anywhere, nothing is cached on disk.

### Settled in this plan (say if you disagree)

1. **Go does the searching** (`internal/space/search.go`): it reads every
   page as the Files tree lists it, takes the Document as plain text (the
   front matter left out; Markdown's marks, link targets and HTML tags
   stripped) and the Canvas's text (each element's `label`, `text` or
   `code`; a frame's or group's name is its label). The open page's
   unsaved text is sent with the request and searched in place of its
   file, so what is on screen is what is found.
2. **Order:** folders and pages whose **name** holds every word first
   (folders before pages), then pages by their number of matches, most
   first; ties in tree order. **At most 50 results**, with "Showing the
   first 50" under them when there are more.
3. **The best match** of a page: the Document line holding the most of the
   words, earliest on a tie; when no Document line holds any, the Canvas
   element doing so, as "On the canvas: <its text>". A page that matches
   only by its name shows its folder path beneath instead. The line is cut
   to about 80 characters around the first match. The count is every
   occurrence of any typed word in the name, Document and Canvas.
4. **Opening a Document match** hands the page's find bar the matched word
   and which occurrence of it to make current (counted in the page's plain
   text, capitals ignored, as find counts). Should the page's own count
   differ (a word inside a link's address, which find does not see), the
   bar starts at the first match. With the Document hidden, the view
   switches to Both.
5. **⌘F goes where the keys are:** to the Canvas's find when the Canvas
   holds focus or the Document is hidden; otherwise to the page's, as now.
   ⌥⌘F (Find and Replace) stays the page's.
6. **Canvas find matches as page find does:** the text typed, anywhere in
   an element's text, capitals ignored (one phrase, not separate words).
   Matches run in reading order: top to bottom, then left to right, by
   each element's box. Outlines are in the ink (`--color-selection-handle`)
   and screen-sized; they do not pulse.
7. **A folder result** focuses its row in the tree (its focus ring shows);
   the tree's selection stays the open page.

## As built

⇧⌘F (File ▸ Search) opens a palette at the top of the window over a
backdrop. Go reads the Space's pages and folders (names, each page's
Document as plain text, its Canvas's texts) and the open page as the window
holds it, unsaved words and drawing included; results come one row per
page or folder with the best match beneath, the typed words marked, names
first, at most 50. A Document match opens the page with its find bar filled
at that match; a canvas match opens the Canvas with the element chosen and
the Canvas's own find bar filled; a folder is unfolded and focused in the
Files tree. ⌘F on the Canvas (when it holds the keys, or the Document is
hidden) outlines every element whose text matches and steps through them.

**Checks:** `go test ./internal/... .` and `go vet` exit 0; `npm test` 2,814
passed and 1 skipped; `npm run check` and `npm run lint` exit 0;
`npm run browser` 490 passed, twice in a row, 286 references; 8 new pictures (the palette empty,

**Deviations**

- **The open page is sent as its text and its Canvas**, not as one file's
  text: the window holds them apart. `OpenPage` is `{path, source, scene}`.
- **The Canvas's find bar floats at the canvas's top right** (`FindBar`
  `look="floating"`): across the top it ran under the tool rail.
- **The field's placeholder is "Search"**; the hint beneath says "Search
  pages, folders and canvases", so the two do not repeat each other.
- **Revealing a folder clears a tag filter** first, or its row would not
  be drawn.
- **The Canvas's find closes** when another page opens or the Canvas is
  hidden, and its matches are found again whenever the drawing changes.
- `search-marks.ts` and the stage's outlines following a moved match were
  written with their tests in the same step, not red first.

**Review:** two blockers, both fixed with a test that failed first:
search crashed on a letter whose lowercase takes another number of bytes
(the Kelvin sign, a Turkish dotted I), as offsets into the lowered text cut
the original; matching now runs in characters. A folder found kept taking
the keys back whenever the tree changed (where Backspace trashes it); the
reveal now happens once per request. Also fixed: ⌘F goes to the Canvas
only when nothing else holds the keys or its own bar does (a focused tree
row now sends it to the page); the palette is a modal that keeps Tab, its
notes sit outside the list of results, its icons are named, and its Esc is
a key box from `messages.ts`; Go reads no label from lines and strokes, as
the Canvas's find does not; an unreadable page and folder are tested and
the skip commented; the `scrollIntoView` test stand-in shared in the test
setup; tests added for focus coming back after Esc, a folder found leaving
the open page chosen, and ⌘F in Both. Left: a Document match whose
occurrence is past the first is covered by Go's and the editor's tests,
not a browser test (the fixtures hold no such page).
