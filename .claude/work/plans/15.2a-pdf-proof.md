# 15.2a: Proof that each system prints a PDF

**Goal:** a Go package that has each system's webview print a given HTML
page to a PDF file at a chosen paper size, orientation and margins,
proven by the real app on CI on macOS, Windows and Linux.
**Specs:** `.claude/work/specs/export.md` decisions 1, 3, 4 and 6
(2026-10-11); `.ai/rules/wails.md` (thin native surface, main thread,
GTK4 and WebKitGTK 6.0 on Linux, CI for cross-platform claims);
`docs/testing.md` (end-to-end on CI only).
**File format impact:** none.
**UI impact:** none. Nothing a person sees changes; the proof runs only in
the end-to-end build.

## Constraints

- **No service of ours, nothing leaves the machine:** each system's own
  webview prints; no PDF service, no browser downloaded.
- **Never launch the app locally.** The native code is proven only by the
  end-to-end runs on CI (`wails3 build EXTRA_TAGS=e2e`, all three systems).
  What can run on the host (page sizes, reading a PDF back) is unit-tested.
- **Thin native surface** (`wails.md`): the package takes HTML and a page
  setup and writes a file; it knows nothing of pages, Spaces or the dialog.
- **The main thread:** AppKit and GTK calls run through Wails'
  `application.InvokeSync`; a handler that panics there must not leave the
  caller blocked (`wails.md`, the PanicHandler rule).
- **Windows:** Wails' WebView2 code is in its `internal/` tree, which
  another module may not import. *As built:* nothing is copied; a hidden
  Wails window loads the page and its WebView2 object is reached by name
  at run time, to call Chromium's own `Page.printToPDF` in process (see As
  built).
- **A stop rule:** if a system's printing still fails after three CI
  attempts with a root cause found each time, stop and bring the choice
  back (decision 6): that system's PDF is decided before 15.2c.

## Tasks

### Task 1: Page setup and reading a PDF back
**Files:** `internal/pdfprint/setup.go` (+ test), `internal/pdfprint/inspect.go`
(+ test, with small PDFs written by hand under `testdata/pdf/`).
**Behavior:** `PageSetup{Paper, WidthMM, HeightMM, Landscape, Margins
{Top, Right, Bottom, Left mm}, Background}`; the named papers of decision 3
(A3, A4, A5, B4, B5, Letter, Legal, Tabloid) to millimetres, Custom as
given, landscape swapping the sides; the default by region (Letter for US
and CA, A4 otherwise); the margins of decision 4 (None 0, Narrow 12,
Normal 20, Wide 30 mm). `Inspect(path)`: a PDF's page count and each
page's size in millimetres (from its MediaBox), to check what was printed.
- [x] Failing tests: each named paper's size; landscape swaps; Custom
  kept; the region default; each named margin; a PDF of 2 A4 pages reads
  as 2 pages of 210 × 297 mm; a file that is not a PDF is refused
- [x] Implement
- [x] Green: `go test ./internal/pdfprint`

### Task 2: macOS
**Files:** `internal/pdfprint/print_darwin.go` (cgo, Objective-C).
**Behavior:** a WKWebView of its own, never shown, the page's size, loads
the HTML; when loaded, prints it with `printOperationWithPrintInfo:` set
to save to the file (paper size, orientation, margins, backgrounds printed),
no panels shown; returns when the file is written, or an error.
- [x] Implement; builds with `go vet` on the host (`GOOS=darwin`)

### Task 3: Linux
**Files:** `internal/pdfprint/print_linux.go` (cgo, WebKitGTK 6.0, GTK4).
**Behavior:** a WebKitWebView of its own in a hidden window loads the HTML;
when loaded, a `WebKitPrintOperation` with `GtkPrintSettings` printing to
a file (`output-uri`, PDF) and a `GtkPageSetup` (paper, orientation,
margins) prints without a dialog; returns when done, or an error.
- [x] Implement; builds on CI's Linux job

### Task 4: Windows
**Files:** `internal/pdfprint/print_windows.go`.
**Behavior:** a hidden Wails window loads the HTML; when loaded, Chromium's
`Page.printToPDF` (paper width and height and margins in inches,
backgrounds), called through the window's WebView2 in process, returns the
PDF, written to the file; returns then, or with an error.
- [x] Implement; builds on CI's Windows job

## As built (before CI)

`internal/pdfprint`: page setup (the named papers and margins, Custom, the
region's default) and `Inspect`, which reads a PDF's pages and their sizes
object by object, rotation and inherited boxes included. Printing per
system: **macOS**, a WKWebView of its own in a window never shown, printed
with `printOperationWithPrintInfo:` saving to the file, run modally on that
window; **Linux**, a WebKitWebView in a GTK window never shown, a
`WebKitPrintOperation` to GTK's file printer; **Windows**, a hidden Wails
window and Chromium's `Page.printToPDF` through its WebView2, reached at
run time. macOS and Linux share their Go half (`print_cgo.go`); a build
without cgo, or with Wails' `gtk3` tag, gets a stub that says printing is
not available. The end-to-end build has a `pdf` step and the
`export-proof` walk: A4 portrait, Letter landscape and A3 with no margins,
each read back, the PDFs kept with the run's downloads.

**Deviations:** nothing copied from Wails, so `NOTICE` is unchanged (the
Windows approach above); macOS and Linux make their own webview rather
than reaching the window's, as nothing of the app's window is printed.

**Review:** three blockers, fixed: Linux freed its record on a failed load
or print and then used it again (WebKit sends a last "finished" after a
failure), which would have crashed; it now notes a failure and reports and
frees once, at the end; the job test used `/tmp/x.pdf`, which is not an
absolute path on Windows. Also fixed: the print operation is released; on
Windows a Wails change fails the print with a message (kinds and the
method's signature checked, a recover), a late print never reaches a closed
window, and no report can block the main thread; macOS tears down after the
print operation returns; Linux is skipped under `gtk3`; the settle delay
and pixel sizes named; errors name their file; `Inspect` reads rotated
pages. Left for 15.2c: cancelling a print that timed out (its webview lives
on until it reports), a locale-proof name for GTK's file printer, and
loading pages larger than WebView2's 2 MB `NavigateToString` limit.

**What to read the first CI run for:** Linux PDFs written with compressed
object streams (the page count then comes from the page tree; a size
failure would mean the boxes are packed too); a Windows refusal of
`Page.printToPDF` outside headless Chromium; blank macOS pages.
