# 15.2b: Export dialogs, and the Markdown zip

**Goal:** export is grouped by what is exported: File ▸ Export ▸ Page,
Canvas, Space, each its own dialog; a page, a folder or the Space exports
as a Markdown zip; the canvas exports as today.
**Specs:** `.claude/work/specs/export.md` decisions 2 and 7 (2026-10-11);
`.claude/work/specs/documents.md` decisions 48 and 60 (the page's ⋯
menu); `docs/ipc.md`; `docs/file-format.md` (Spaces, `.bava/`);
`.ai/rules/design-system.md`, `ipc.md`, `file-format.md`.
**File format impact:** none. A zip holds the Space's own files as they
are; nothing new is written into a Space.
**UI impact:** added: `PageExportDialog`, `SpaceExportDialog` (each a
preview of what the zip holds beside its options, then Export); reused:
`Dialog`, `Select` (the folder to export), `ConfirmDialog` (a loose page),
the canvas's `ExportDialog` retitled "Export canvas". Strings in
`messages.ts`; tokens added first if any are needed.

## Constraints

- **Grouped by what is exported** (decision 2): File ▸ Export opens a
  submenu, Page, Canvas, Space. The page's ⋯ menu and a page's right-click
  in Files open the Page dialog; a folder's right-click opens the Space
  dialog set to that folder; the Space switcher's Export Space opens it for
  the whole Space; the canvas's right-click and File ▸ Export ▸ Canvas open
  today's picture export, unchanged but for its title.
- **What a zip holds** (decision 7): a Space's zip is every file of the
  Space as it lies, with `.bava` but not its Trash (the images and files,
  the templates, the settings), so it reopens as the same Space.
- **Go owns the files** (`ipc.md`): it lists what a zip will hold and
  writes it; the frontend shows the list and says which files a page uses.
  Errors are data with a `code`; the root is checked; nothing follows a
  link out of the Space; nothing reaches the network.
- **A zip is written like a save:** to a temporary file beside the target,
  renamed into place, so a failure never leaves half a zip.

### Settled in this plan (say if you disagree)

1. **A page's or a folder's zip keeps them where they sit in the Space**:
   `Marketing/Launch plan.md` stays under `Marketing/`, with
   `.bava/attachments/` at the zip's top holding only the files those pages
   use (images, videos, files, a canvas embed's picture). Every link to an
   attachment then still works unchanged, and the zip opens as a Space.
   No templates and no settings: they belong to the whole Space.
2. **Links to pages left out of a page's or folder's zip stay as written**;
   opened as a Space they show as missing links, as any broken link does.
3. **Until 15.2c the Page and Space dialogs export only the Markdown zip**;
   the Format choice (PDF or Markdown zip) arrives with PDF.
4. **The preview lists what the zip will hold**, from Go's own list:
   folders and pages as a tree, then the hidden folder's parts in a line
   each (attachments, templates, settings) with their counts, and the
   total size at the dialog's foot ("12 pages · 9 files · 1.2 MB").
5. **The file is chosen with the system's save dialog**, named after what
   is exported (`Launch plan.zip`, `Marketing.zip`, `Acme Product.zip`).
   A loose page has no Space, so its Page dialog offers the zip only after
   opening its folder as a Space, as embeds and search do.
6. **File ▸ Export ▸ Canvas is today's File ▸ Export**: the same command
   (`file.export`) under its new place, so its shortcut-free menu item and
   every test of it hold.

## As built (2026-10-11)

Built as planned: File ▸ Export is a submenu (Page, Canvas, Space); a page's
right-click and ⋯ menu open Export page; a folder's right-click and the
Space switcher open Export Space; Go plans and writes the zip
(`internal/space/zip.go`, `ZipPlan`, `ExportZip`), through the store's
atomic write, reading through the Space's rooted file system.

**Deviations**
- **A bug from before, fixed on the way:** a folder's right-click read which
  menu was open after clearing it, so New page and New folder from a folder
  landed in its parent, and Export went to the page's dialog. Now read
  first; a browser test covers New page from a folder.
- **An unsaved page is saved before its export**, and the export stops,
  saying so, if that save fails. Not in the plan; a zip holds files as saved.
- **A new refusal code, `notPage`,** for a page scope that names a folder.
- **The `zip` step splits its parts on `;`**, so names may hold spaces.
- **Tests written with their code in one step** for `zip-preview.ts`, not
  seen failing first.
- **The loose-page browser test checks only the offer**: the stand-in
  cannot open a folder that is not a seeded Space, the same limit search's
  loose-page test has. What follows a yes is the path embeds and media take.
