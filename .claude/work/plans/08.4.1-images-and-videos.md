# 08.4.1: Attachments, images and video files

> Historical: built and committed; see the roadmap for what followed.

**Goal:** images and video files go into a page by paste, drop, the `/`
menu or a file picker, are copied into the Space's hidden attachments
folder, and show in the page: images sized, cropped, aligned and captioned,
videos playing in place.

**Specs:** `.claude/work/specs/documents.md` decisions 6, 10, 11 (the
attachment's menu), 30, 31, 33, 52, 54, 88, 89, 92, 93, 96 and 97;
`docs/file-format.md` ("The document", "Invisible marks", "Spaces");
`docs/ipc.md`; `.ai/rules/editors.md`, `.ai/rules/file-format.md`,
`.ai/rules/wails.md`, `.ai/rules/ipc.md`, `.ai/rules/design-system.md`.

**File format impact:** yes, specified first (Task 1).
- `.bava/attachments/`: the folder, its naming rules.
- **Images and video files:** a Markdown image alone on its line, its
  settings in the mark above (decisions 92 and 93).
- **The mark's new keys:** `width`, `ratio`, `align`, `caption`, `poster`,
  `loop`, `muted`.

**UI impact:**
- **Blocks:** an image block and a video block in the Document.
- **Menus:**
  - the media's menu, from the block;
  - `/` gains Image and Video, in Advanced.
- **Components:**
  - `MediaViewer` (an image full screen), over Ark UI's Dialog;
  - the caption field reuses the pattern of `LinkField`.
- **Tokens:** for the media block, its caption and the missing state.

## Constraints

- **Files are the source of truth** (non-negotiable 2).
  - An attachment is a plain file in `.bava/attachments/`.
  - Nothing about it lives anywhere else: "unused" is worked out, never
    stored.
  - An untouched page still saves byte for byte.
- **No network in this part.** Online media is 8.4.2.
- **Naming** (decision 10):
  - A file keeps its name.
  - A different file with the same name is saved numbered (`logo 2.png`).
  - An identical file (same bytes) is reused, stored once.
  - A pasted image with no name is `Pasted image 2026-09-29 14.32.05.png`.
- **Addresses:**
  - A media block's address is relative to its page, `%20`-encoded, as a
    page link is (decision 88). Moving or renaming a page, or renaming an
    attachment, rewrites it everywhere, through the Document's own reader
    (decision 89).
  - A value in the mark that names an attachment (`poster`) holds the file
    name only: it is always in the attachments folder, so moving a page
    never changes it.
- **Which files a page can show:**
  - The app serves images and videos to the page only from inside a Space
    it opened (the attachments folder included), or from the folder of a
    page it opened on its own.
  - Never anything else, never through a link, and only image and video
    types.
- **Videos never play by themselves** (decision 33). They play in place,
  with the webview's own player; loop and mute apply once playing.
- **A playing video survives edits elsewhere:**
  - The block is drawn once, by its own node view.
  - Its settings change the drawn video in place.
  - Clicks and keys on the player stay with the player.
  - The player's own changes to its DOM are ignored.
  - It restarts only when it is moved, deleted, undone away, or the page
    reloads.
- **A loose page** (decision 52): adding media offers to open its folder as
  a Space; declined, nothing is added.
- **Missing media** (decision 96):
  - It shows as missing.
  - It offers "Relink to <file>" when one file of that name is in the
    attachments.
  - Nothing changes until that is pressed.
- **Formats:**
  - Images: PNG, JPEG, GIF, WebP, SVG (shown as an image, so no script in
    one runs).
  - Videos: MP4 (H.264, which plays everywhere), WebM and MOV.
  - A video the platform cannot play shows its poster and says so.
- **What stays as it is:** an image inside a line of text (a badge, an
  inline icon) is kept as written, as today; only an image alone on its
  line is a media block.

### Task 2: The attachments folder (Go)
**Files:** create `internal/space/attachments.go` and its tests; modify
`internal/app/space.go` (`Apply` kinds `attach`, `attachData`,
`renameAttachment`; `OpResult.Name`), and `docs/ipc.md`.
**Behavior:**
- **Attaching:**
  - `attach` copies a file from anywhere.
  - `attachData` writes pasted bytes (base64) under a name.
  - Both follow the naming rules, reuse an identical file (compared by
    size, then SHA-256), never overwrite, and return the name used.
  - Written through a new `store.SaveBytes` (atomic, keeps permissions).
- **Renaming:** `renameAttachment` renames within the folder, refusing a
  taken or invalid name.
- **Safety:** paths are checked as the Space's are. The folder is made on
  first use.

## As built (2026-09-29)

All nine tasks built test-first; every gate passes by its exit code: `go vet`,
`go test ./...`, `npm run check`, `npm run lint`, `npm test` (2384 passed, 1
skipped), `npm run build`, `npm run visual` (128 passed).

**Deviations from this plan:**
- **Images on the web are shown** (the user's choice, after the first
  report): an image at `https://…` loads when the page shows it; a video on
  the web loads nothing until play. `/…` and other schemes stay kept.
  Recorded in `docs/file-format.md` and `docs/decisions.md`.
- **The spec's first example wrote `align=center`**, which its own rule says
  is never written (centred is the default). The example now leaves it out.
- **`store.SaveFrom`** (a stream) instead of `store.SaveBytes`; `Save` uses it.
- **Unnamed pasted bytes are named by Go** (`attachData` with no `name`), not
  by the page.
- **The media picker is per kind** (`FileService.ChooseMedia("image" |
  "video")`), several files at once.
- **"Show in folder"**, as everywhere else in the app, rather than "Show in
  Finder / Explorer".
- **Rename file is offered only for an attachment**; a medium elsewhere in
  the Space is renamed from the Files tree.
- **`LinkField` takes the caption and the new file name** (`placeholder`,
  `removeLabel`) rather than a new component. It now focuses once its portal
  has put it in the page.
- **A field or the viewer opened from the media menu opens a frame later**:
  Ark's menu could focus itself after the field had, found by tracing focus
  in the walk. Rule added to `.ai/rules/editors.md`.
- **A media block is `loading` until its file loads**, then `ready`: the
  smoke run waits on it, so it proves the file route in the real app.
- **An image inside a line of text does not follow moves**: it is kept text,
  and the read-back check would refuse a rewrite of it.

**Not proved by a test:**
- Taking a video's frame as its poster (`videoFrame`): jsdom decodes no
  video. The naming (`posterName`) and saving path are tested.
- The app's glue for Replace, Rename and the poster (`App.svelte`): the
  pieces each is made of are tested (`renameAttachment`, relinking, the menu).
- The smoke steps (an image added through the picker, found loaded after
  reopening) did not start in this session's shell; CI runs them.
- A video actually playing: the container's WebKit has no H.264, so the walk
  shows the poster of a video still loading, and checks the same player
  survives typing.

**Spec review: FAIL, two blockers, both fixed; every warning fixed.**
- **Windows paths escaped the file route** (`a\..\..`, `C:`, shares): `\`
  and `:` are refused on every platform, and the file is opened through
  `os.OpenRoot`, which also closes the gap between the checks and the open.
  The edges of the attachments exception are tested, and a dot-file inside
  it is refused.
- **An image by reference (`![x][r]`) was rewritten on save**: it stays kept
  text, as before.
- Also fixed: a poster written without quotes keeps that form when renamed;
  every file served is `nosniff` and sandboxed; two files attached at once
  never share a name; a loose page's media menu offers nothing that needs a
  Space; a page at the root of a disk loads its images; a poster's name
  ignores the query; the viewer has a name when the image has no words; the
  relink button has a focus ring.
