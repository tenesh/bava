# 05.8: Errors and logs

**Goal:** When something fails, the user sees what happened and can hand us the
logs — and nothing reaches us unless they send it.

**Specs:**
- `.claude/work/specs/errors-and-logs.md` — design and three decisions
  (retention, verbose logging, Report Issue hidden)
- `CLAUDE.md` non-negotiables 1 and 2 — no service of ours; Bava's own state
  lives outside the project
- `.ai/rules/wails.md`, `.ai/rules/ipc.md`, `.ai/rules/svelte.md`,
  `.ai/rules/design-system.md`
- `.claude/plan/roadmap.md` — Milestone 5.8

**File format impact:** none. Logs and the session marker are Bava's own
state in the platform log folder, never in a user's project.

**UI impact:**
- Added:
  - `ErrorDialog` (wraps `Dialog`, with a collapsible details section wrapping
    Ark Collapsible)
  - `PanelBoundary` (a `<svelte:boundary>` with a fallback)
  - Settings ▸ Advanced section
- Reused: `Dialog`, `Segments`, `StatusBar` message.
- Tokens: none expected; any found missing are added before use.

## Constraints

- **No service of ours.** Nothing is uploaded, ever. Copy Diagnostics writes to
  the clipboard; Open Logs Folder opens a local folder. Report Issue… is built
  but hidden (decision 2026-09-17).
- **A log never contains** document prose, D2 source, canvas content or labels,
  AI prompts or replies, credentials, or the home directory (written `~`).
- **Retention, verbatim:** the newest 10 sessions, 50 MB total, current session
  never pruned.
- **Verbose logging:** a setting, off by default; default level records
  warnings, errors, and session start and end.
- **Log folders:**

  | Platform | Folder |
  |---|---|
  | macOS | `~/Library/Logs/Bava` |
  | Windows | `%LOCALAPPDATA%\Bava\logs` |
  | Linux | `$XDG_STATE_HOME/bava/logs`, default `~/.local/state/bava/logs` |

- **Measured in the pinned Wails beta.20:**
  - the production `DefaultLogger` discards everything
  - the default `PanicHandler` exits the process
  - bound-method panics already reject the call
  - the webview content-process termination event exists for macOS only
- **Bound surface stays small:** one new service, `LogService`.
- No version stamping exists before Milestone 16: diagnostics say so rather
  than inventing a number.

## Tasks

### Task 1: `internal/logs` — session files, pruning, redaction
**Files:**
- create `internal/logs/logs.go`
- create `internal/logs/logs_test.go`

**Behavior:**
- **`Dir(goos, env)`** returns the folder for each platform from injected
  environment values (home, `LOCALAPPDATA`, `XDG_STATE_HOME`), so every
  platform is testable on one machine.
- **`Start(dir, now, level)`:**
  - creates the folder
  - opens a session file named `2006-01-02T15-04-05-<pid>.log`
  - prunes older sessions to 10 files and 50 MB, never the new one
  - returns a `Session` holding a `*slog.Logger`
- **Level:** the level is a `slog.LevelVar`, so `SetVerbose(bool)` switches
  between Warn and Debug at runtime.
- **Size cap:** a session holds 50 MB at most. Past that, the writer rolls to
  `<name>.1.log`, replacing any earlier roll, so the newest lines are always
  kept. This refines the spec's "truncated from its start" into something with
  no rewrite of a live file; the spec is updated to match.
- **Redaction:** the handler replaces the home directory with `~` in the
  message and every string attribute.

### Task 4: `LogService` — the one new binding
**Files:**
- create `internal/app/log.go` and `internal/app/log_test.go`
- modify `main.go`
- regenerate bindings

**Behavior:**
- **`Report(entry)`** logs a frontend error.
  - The entry carries level, message, stack and where it came from.
  - The message is capped at 2,000 characters and the stack at 8,000.
  - Rate limit: 20 entries per 10 seconds, then a single "suppressed N" line
    when the window closes.
- **`Diagnostics(userAgent)`** returns plain text:
  - the Bava version (from `debug.ReadBuildInfo`, "unstamped development
    build" when absent)
  - OS, architecture and OS version
  - the webview user agent
  - whether the previous session ended unexpectedly
  - the last 200 lines of the current session's log, already redacted
- **`OpenLogsFolder()`** reveals the folder through
  `EnvironmentManager.OpenFileManager`, injectable for tests.
- **`TakeNotices()`** returns, once, the startup notices: the previous session
  ended unexpectedly, or the webview was reloaded after its process died.
- **`SetVerbose(on)`** changes the level and saves the preference through
  `internal/config`.
- **`main.go`:**
  - starts the session before `application.New`
  - passes `Options.Logger`
  - closes the session in `OnShutdown`
  - replaces both `log.Fatal` calls with a logged error, a native error dialog
    and an exit

- [x] Failing test: `TestDiagnosticsNamesTheBuildAndRedacts`

### Task 8: What the user sees
**Files:**
- create `frontend/src/shell/errors.svelte.ts` and its test
- create `frontend/src/components/ErrorDialog.svelte` and its test
- modify `App.svelte` and `messages.ts`

**Behavior:**
- **`errors.svelte.ts` holds the policy:**
  - the first unexpected error in a session opens the dialog
  - later ones only show a status-bar notice ("Another error was logged"), so
    a failure in a loop cannot stack modals
  - a startup notice opens the dialog once, in its "closed unexpectedly" or
    "window reloaded" wording
- **`ErrorDialog`** is presentational:
  - a title
  - one plain sentence
  - a Details section, collapsed by default, holding the summary and log id
  - buttons for Copy Details, Open Logs Folder and Close
  - no Report Issue while hidden
- **Sources:** `app:error` events and `installErrorHandlers` both feed the
  policy.

## Status — 2026-09-17

Tasks 1–11 implemented and gated. Open: the keyboard pass on `ErrorDialog`, and
the human check at a release build (force a panic and a frontend exception;
find both in the log folder).

Deviations:
- `main.go`'s fatal paths log and write to stderr, then exit, rather than
  showing a native error dialog: they fail before the application runs, when
  Wails dialogs are unavailable. Both are build defects (a corrupt embedded
  menu spec, a failed `Run`), not user-reachable states.
- Logs carry no file paths or names at all (stricter than the plan's "home as
  `~`"), found while writing Task 11.
- Added `Disclosure` (wraps Ark Collapsible) for `ErrorDialog`'s details, and
  an ESLint `argsIgnorePattern: '^_'` for positional snippet parameters.
- Added debug-level log lines to `Open`, `Save` and `Render` (sizes, counts,
  durations), which verbose logging promised and Task 11 needed to exercise.

Spec review fixes (all 16 findings verified against the pinned Wails source):
- **Blocker:** Wails logs every bound call's arguments at debug level. Wails
  now gets `Session.WailsLogger()` — warn and above, attribute values redacted.
- **Blocker:** a panic inside `InvokeSync` would hang its caller if the handler
  returned. The handler now logs and exits in that case.
- Frontend reports and the dialog's details carry an error's kind and frames,
  never its message; Go's `app:error` carries only an id.
- Per-session markers keyed by PID: two instances neither report each other as
  crashed nor prune each other's live logs; each crash is reported once.
- A failed roll keeps logging; a failed prune warns instead of failing start;
  the fallback folder is per-user; the last resort is a discard session, not an
  exit. Folders 0700, files 0600. Orphan rolls pruned.
- Verbose is saved before the level changes. Truncation keeps whole UTF-8
  characters. The session closes after `Run` returns. The app pointer is atomic.
- Error-dialog strings and the issue template moved to `messages.ts`. The
  dialog is keyed on the queued item so an Escape-dismissal cannot leave the
  next item invisible — **no test covers this App-level wiring**; it needs the
  keyboard pass at a window.
- Docs corrected: retention while running, when the suppressed count is noted.
