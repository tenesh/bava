# 15.4c: Paste from other apps, and pictures on the canvas

**Goal:** shapes travel between Bava windows and pages through the system
clipboard, text from anywhere pastes onto the canvas, and pictures become
canvas elements.
**Specs:** `.claude/work/specs/canvas-work.md` decisions 8 to 12;
`docs/file-format.md`; `.ai/rules/canvas.md`.
**File format impact:** part 2 adds the `image` element (below), with a
round-trip test. Part 1 none.
**UI impact:** part 2, drawn as the mockup's "4.10 Pictures on the canvas".

Two parts, each its own commit and CI run: part 1 the clipboard, part 2
the picture element.

## Constraints

- "Copied shapes go on the system clipboard as an SVG picture, with Bava's
  own data inside it, so Bava pastes them back as the same shapes in any
  window or page." The clipboard carries text only.
- "Text pasted from another app becomes one text element, its line breaks
  kept, wrapped at a set width; one undo step."
- What is pasted lands under the pointer when it is over the canvas, else
  in the middle of the view.
- Bindings are ids: a pasted arrow attaches to the pasted shapes, and lets
  go of a shape that was not copied with it (`edit.ts` `paste`).
- Undo is one step per paste.

# Part 1: the clipboard

## How it works

- **Copy and Cut on the canvas** keep today's in-window clipboard and also
  write the selection to the system clipboard: the SVG Copy as SVG already
  makes (`exporter`), with the copied elements, as the file stores them,
  inside it: `<metadata id="bava-canvas">{"version":1,"elements":[...]}</metadata>`,
  the JSON escaped for XML.
- **Paste on the canvas** reads the system clipboard's text:
  - Bava's SVG (`clipboard-read.ts`, new, `readCanvasClipboard`): its
    elements, pasted with fresh ids as today (`edit.paste`), arrows and frames
    pointing at the copies. In the same page and with their spot in view
    they land where today's paste puts them (offset by `PASTE_OFFSET`);
    otherwise their middle lands under the pointer or in the view's middle.
  - Any other text: one `text` element holding it, line breaks kept, its
    width the smaller of its longest line and `PASTED_TEXT_WIDTH` (scene
    units), wrapped there; measured and stored as text always is.
  - Nothing (or only a picture, until part 2): nothing happens.
- **Paste in the page** of Bava's SVG inserts nothing, and the status bar
  says shapes paste on the canvas; any other text pastes as today.
- Copy as SVG (`canvas.copySvg`) is unchanged: a picture for other apps,
  without Bava's data.

# Part 2: pictures on the canvas

## How it works

- **The element** (file format): `{ "type": "image", "file": "har gow.png",
  "x", "y", "w", "h", "z" }`, `file` the attachment's name in the Space's
  `.bava/attachments/` (never a path, so moving the page never breaks it,
  as a video's `poster`). Takes `opacity`, `angle`, `locked`, `frame`; no
  fill, border or label. Unknown keys kept, as every element's.
- **Drawn** on the stage as a `Konva.Image`, the picture loaded outside the
  stage from `/bava-file/?root&path=.bava/attachments/<file>` (the route
  page images use) and handed in, as highlighted code is (`setPicture`); a
  file that cannot be loaded draws the missing placeholder (mockup 4.10).
- **Resizing keeps its proportions**; Shift frees it (decision 12).
- **Added four ways**, each attaching the file first exactly as the page
  does (`attach` / `attachData`, a page outside a Space asked to open its
  folder as one), then placing it at its own size, at most
  `PICTURE_MAX_SIDE` on its longer side, centred where it lands:
  - Paste with a picture and no text on the clipboard;
  - a file dropped on the canvas (the drop's point tells the canvas from
    the page; today every drop goes to the page);
  - File ▸ Picture… (beside Diagram from Code, `when: hasDocument,
    showsCanvas`) and the canvas's + menu: the image picker;
  - a picture dragged from Media (its `application/x-bava-attachment`),
    reusing the attachment.
- **Media sees canvas pictures**: a page's use includes its canvas's
  `image` elements (the open page's from the scene in hand, others' from
  their files); renaming an attachment rewrites `file` in every page's
  canvas, the open one through history; Trash Unused never takes one in use.
- **Exports draw it**: the SVG (and so PDF pictures, frame embeds and the
  part 1 clipboard SVG) embeds each picture as a data address, its bytes
  fetched first as fonts are; the PNG preloads them for the offscreen stage.
- **Pasting Bava's SVG into another Space**: a picture whose file that Space
  lacks is attached from the bytes inside the SVG, so it arrives whole.

## As built

### Part 1

- Copy and Cut on the canvas keep the window's own copy (`commands.copied`)
  and write `exporter.carrying(elements)` to the system clipboard: Copy as
  SVG's picture with `<metadata id="bava-canvas">` (`CARRIED_VERSION` 1).
  `readCanvasClipboard` takes only that version, known element types, and
  finite `x`, `y`, `w`, `h`, `z`.
- Paste on the canvas always reads the system clipboard, after any copy
  still being written. The in-window `paste()` and `canPaste` are gone;
  `pasteElements(elements, at?)` pastes with fresh ids in one step, selecting
  the copies of the top-level elements.
- "The same page" is the last copy or cut of this window, in the scene it
  came from (counted per scene load), unchanged, its spot in view: pasted
  offset by `PASTE_OFFSET`, so Cut then Paste puts shapes back beside where
  they were. Anything else lands centred on the spot.
- The spot is where the right-click menu opened, for its Paste; else the
  pointer over the canvas; else the view's middle.
- The right-click menu offers Paste when the system clipboard holds text,
  read as it opens.
- Pasted text goes through `pasteElements`, so it gets an id of its own.
- A text element narrower than its longest line (`isWrapped`) stays wrapped
  at its width while typed into and after: the field wraps (`wraps`), and its
  size is `textSize`.
- The clipboard wrapper is `src/ipc/clipboard.ts`, a stand-in in browser
  tests (`tests/harness/fake-clipboard.ts`).
- Owed at a running window: three lines in `docs/release-checklist.md`
  (Canvas).

### Part 2

- The `image` element (`scene.ts` `ImageElement`) round-trips in Go
  untouched (a contract test, `TestRoundTripPictures`); its toolbar offers
  only opacity.
- The stage draws it from pictures handed in (`setPicture`, `clearPictures`),
  loaded by `pictures.ts` once per file of the open Space, all of it (loads
  under way too) dropped when the Space changes, and the missing looked for
  again whenever Media is read afresh. While loading it shows the placeholder's box and icon;
  the name and "Not in the Space's attachments" once it is known missing.
  The layout is `picture-placeholder.ts`, shared with the SVG export.
- A selection holding a picture keeps its proportions; Shift frees it.
- `PICTURE_MAX_SIDE` is 480 scene units; a picture of unknown size (an SVG
  without one) is a 240 square. Several pictures land side by side, their
  row centred on the spot, one undo step.
- The canvas region is a file drop target (`data-file-drop-target`), as the
  Document is; a drop is told from one on the page by its point. Only
  pictures go on the canvas; anything else stays out, with "Only pictures go
  on the canvas" in the status bar. File ▸ Picture and the + panel's Picture
  open the picture picker; a Media drag reuses the attachment.
- Media counts the open page's canvas pictures from the scene in hand, and
  other pages' from their files' canvas blocks (`page-pictures.ts`, found by
  the Go reader's fence rules: the last top-level block). A rename rewrites
  only the `"file"` values in each other page's canvas block (written only if
  unchanged since read; a value written some other way is reported missed),
  and the open canvas in one undo step.
- Exports take `pictures` by file: data addresses for files, the clipboard,
  PDF pages and frame embeds (`pictures-data.ts`); the app's own address
  for the dialog's preview. A missing one exports as its placeholder.
- Bava's copied SVG names each picture's file on its `<image data-file>`;
  pasted, the carried bytes are always attached: Go reuses a file with the
  same bytes, else gives a free name (`carriedPictures`).
- The canvas region carries `data-pictures` (`loading` or `ready`) so a
  browser test can wait for pictures; `openCanvas` does.
- The browser stand-in now attaches files (`attach`, `attachData`, a file of
  the same name standing in for the same bytes), answers the picture picker
  and a clipboard picture, and its index holds a page's canvas block, as the
  file does.
- Owed at a running window: four lines in `docs/release-checklist.md`
  (Canvas).
