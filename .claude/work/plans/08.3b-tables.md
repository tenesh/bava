# 08.3b: Rich tables

**Goal:** tables in the Document can be edited as tables:
- cells, rows and columns;
- alignment, merged cells, cell colours, column widths, a header row and a
  header column;
- paste from a spreadsheet.

Each table is saved in a form other apps draw.

**Specs:** `.claude/work/specs/08-documents.md` decisions 20, 43 (paste of
spreadsheet cells), 51, 77, 83 to 86; `docs/file-format.md` ("The document");
`.ai/rules/editors.md`, `.ai/rules/file-format.md`,
`.ai/rules/design-system.md`.

**File format impact:** yes, specified first (Task 1). Tables stop being kept
blocks and become editable. The format has two forms:
- **Markdown table:** used while a table is plain.
- **HTML table:** used once it uses a rich option (decision 85).

**UI impact:**
- **The table in the page:** cells, a column-resize edge, a row and a column
  handle, and `+` edges to add a row or column.
- **A table menu:** from the handles, and from a right-click in a cell.
- **`/` menu:** gains Table, in Advanced.
- **Tokens:** for the table's lines, handles and selected cells.
- **Components:** no new one; the menus are `ContextMenu`.

## Constraints

- **Nothing is lost** (non-negotiable 2). A table Bava cannot hold exactly
  stays kept, byte for byte, as today. That covers:
  - an HTML table not in Bava's own shape;
  - a Markdown table with a row longer than its header, whose extra cells
    Markdown readers drop;
  - a table whose cells hold blocks.

  An untouched page still saves exactly as read.
- **Two forms** (decision 85):
  - **Markdown table:** a header row, cell text and each column's alignment
    (`:---`, `:---:`, `---:`).
  - **HTML table:** used as soon as the table has any of these:
    - a merged cell;
    - a cell colour;
    - a column width;
    - a header column;
    - no header row.

    The HTML uses `<table>`, `<colgroup><col width="…">` when widths are
    set, `<tr>`, and `<th>` / `<td>` with `colspan`, `rowspan`, `align`
    and `data-background="<swatch>"`.
- **Cells hold formatted text** (decision 86):
  - One paragraph per cell, with bold, italic, underline, strike, code,
    links, colours, highlights, inline equations and line breaks.
  - A line break is `<br>`.
  - In a Markdown table, formatting is Markdown and `|` is written `\|`.
  - In an HTML table, formatting is HTML (`<strong>`, `<em>`, `<u>`, `<s>`,
    `<code>`, `<a href>`, `<span data-color>`, `<span data-highlight>`),
    which is all GitHub draws there.
- **Library:** `prosemirror-tables` (MIT), pinned exactly, for cell
  selection, merging, splitting and column resizing; `NOTICE` gains it.
  Tables are ProseMirror nodes. Svelte never draws a cell.
- **Paste from a spreadsheet** (decision 43):
  - Rows of tab-separated cells (what Excel, Numbers and Google Sheets put
    on the clipboard as text) become a table.
  - Pasting HTML table cells into a table fills the cells from the caret.
- **Tests:**
  - every table form round-trips;
  - hand-written tables keep what they show;
  - every command with logic has a unit test;
  - screen walks cover each state in both themes;
  - a smoke step inserts a table, types into it, and finds it after
    reopening.

## As built

- **Forms:** read and written as specified. A table Bava cannot hold
  exactly stays kept: a foreign HTML table, a cell holding blocks, or a
  Markdown row longer than its header, detected by counting unescaped pipes
  as markdown-it splits them. Every table in the repo's own docs shows the
  same after a save.
- **Tables are settled on read** (`fixTables`), so rows are as wide as the
  table and a column's width sits on each of its cells.
- **Found by the screen checks:** merging "Ana" and "Design" kept only "Ana".
  The package joins merged cells as separate paragraphs, and a cell holds
  one. Bava's merge now joins the texts with line breaks first; merging empty
  cells gives one empty cell. The package's header-column toggle also flipped
  the header row's corner cell; Bava's own toggles keep the row and the
  column independent.
- **Paste:** the webview's own paste event is handled too (a right-click
  Paste), not only the menu's.
- **Deviations:**
  - Rows and columns are moved from the table menu (Move row up and down,
    Move column left and right), not dragged by a handle.
  - Tab selects the next cell's text, as a spreadsheet does, so typing
    replaces it.
  - The `+` edges add a row at the bottom and a column at the right; rows and
    columns elsewhere come from the menu.
- **Spec review: FAIL, then fixed** (six blockers, each with a test that
  failed first):
  - pasted text with a tab made a table even inside a code block (code now
    takes pasted text exactly as it is);
  - an HTML table with a zero span vanished, and bad spans were reshaped (a
    table's cells must now fill the grid exactly, or it is kept);
  - footnote references and images were lost in the HTML form, and other
    inline HTML made the table read-only (read back as references, kept
    images and kept HTML; `[` written as an entity);
  - link titles were dropped in the HTML form;
  - widths landed on the wrong column under a rowspan (cells are placed on
    the real grid);
  - edge spaces in a Markdown cell changed the second save (trimmed on
    write, as readers trim them).
- **Warnings fixed:**
  - a cell's closing line break is kept;
  - pasting that grows a table is one undo step;
  - a merged cell keeps every pasted text;
  - trailing empty pasted rows are dropped, and a stray quote is kept as
    text;
  - the cell minimum width is read from its token;
  - the + edges are pointer-only (the table menu is the keyboard's way);
  - an unused string was removed;
  - decision 85 names "no header row";
  - merging across a header has a test.
- **Known, not caused here:** outside tables too, an inline equation whose
  TeX has edge spaces reads back as text, and a link href with `"` changes on
  the second save. To handle with the next round of format work.
- **After the user's testing (2026-09-28):**
  - Right-clicking selected cells lost the selection, so Merge did nothing.
    WebKit on macOS selects the word under the pointer; the editor now holds
    the cells through a right-click.
  - Found while checking that fix, on a busy machine: a drag's cell
    selection was replaced by the browser's own text selection read back
    after the mouse was released (1 drag in 12). `keepDraggedCells` keeps
    the cells until the next click or key.
  - Merge is offered only for two or more cells making a rectangle, all
    headers or all body cells; Split only on a merged cell; Move only for one
    row or column with somewhere to go.
  - Header row and column read Add or Remove by their state, and labels
    follow the selection (Delete rows, Align columns, Cells colour).
  - A cell shows no "Type /" hint, and its `/` menu offers only the Inline
    group.
  - ProseMirror's own stylesheets were never loaded, so the browser's
    highlight showed inside selected cells and the gap cursor was invisible.
    Both are loaded now.
  - New walks cover merging a 2 by 2 block and splitting it, header and body
    not merging, moving rows, removing the header row, and a new table's
    cells and `/` menu. The whole suite passed six runs in a row.
- **Second spec review: FAIL, then fixed:**
  - Move was offered next to merged cells where it could not go; the menu
    now asks the move commands themselves (a dry run).
  - ProseMirror's stylesheets brought literal colours (a light blue ring on
    a selected block, a black gap cursor); both now use the theme's tokens,
    and the page states ProseMirror's spacing and ligature rules itself.
  - Also fixed: cells held through a right-click are dropped by the next
    press; Control-click on macOS holds them too; a touch or pen press ends
    a kept drag selection; the "Colour cells" label; two stale references
    removed.
- **CI red after the commit:** a rule hiding the highlight in an inactive
  window used `::selection:window-inactive`, which the production minifier
  rejects. The screen checks pass without it, so it was removed, and
  `npm run build` is now a gate.
