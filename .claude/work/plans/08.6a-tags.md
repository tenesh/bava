# 08.6a: Tags

**Goal:** a page carries tags, shown and edited at its bottom, and the Files
tree can be narrowed to the pages that have chosen tags, with tags renamed,
merged and deleted across the Space.
**Specs:** `.claude/work/specs/08-documents.md` decisions 66 and 75;
`.claude/work/specs/08.6-tags-and-templates.md` decisions 1 to 7
(2026-10-06), which replace decision 66's Tags section and its "under its
title"; `docs/file-format.md` (Front matter); `docs/ipc.md` (`relink`).
**File format impact:** a top-level `tags:` key in a page's front matter,
specified in `docs/file-format.md` before the code that writes it, with
round-trip tests.
**UI impact:** two components added: `PageTags` (the chips at the page's
bottom, with Add tag and its suggestions) and `TagFilter` (the Files
header's list of tags with counts, each with its menu) and `TagsDialog`
(decision 7: every tag with its count, rename in place, several selected
to merge or delete). Reused:
`ContextMenu` for a tag's menu, `ConfirmDialog` for Delete and Merge,
the Files header's icon button. Strings in `messages.ts`; tokens added
first if any are needed.

## The file form

```markdown
---
tags: [launch, q4, road-map]
bava:
  width: wide
---
```

- **Read:** a flow list (`tags: [a, b]`), a block list (`tags:` then
  `  - a` lines) or a single word (`tags: a`). Each tag is shown converted:
  lowercase, each run of spaces a dash (`Road Map` is `road-map`); empty
  ones and repeats are dropped.
- **Write:** only when the page's tags are changed in Bava, then as a flow
  list where the key stood (added last in the front matter when new),
  quoted where YAML needs it; no tags removes the key. A front matter that
  held only the key goes with it, as Bava's settings do.
- Every other line of the front matter is kept as it is.

## Constraints

- A tag is lowercase with no spaces; typing converts (decisions 2 and 3).
- Tags sit after the page's content, before Linked from (decision 4).
- No Tags section: a tag button in the Files header (decision 5). The tree
  then shows the pages with **all** the chosen tags, and the folders that
  lead to them opened; drag and drop is off while filtered.
- A tag's menu: Rename (refused for a name another tag has), Merge into
  (another tag; a page with both keeps one), Delete (asks first, saying how
  many pages change; the pages stay) (decision 6).
- The Tags dialog (decision 7), from the tag list's Manage tags… and the
  Space switcher: search, sort by name or pages, rename in a row, select
  several to Merge into one tag or Delete; both ask first, naming the tags
  and the pages that change.
- Rewriting other pages changes only their front matter, through `relink`
  (each written only if it still reads as it did); the open page changes in
  the editor, as an edit. A page that could not be written is named, as a
  move's missed links are.
- Defaults settled in the plan: a locked page shows its tags but cannot
  change them; the filter lasts while the Space is open; Add tag suggests
  the Space's tags that start with what is typed; a loose page has tags but
  no filter. Tag edits are not in the page's undo, as lock and width are not.
- No Go change. Strings in `messages.ts`; tokens only.

## As built

A page's tags sit at its bottom, in the page's column, before Linked from:
grey chips, each with a remove button, then Add tag, whose field writes
what is typed as a tag is kept and suggests the Space's tags above it. The
Files header has a tag button: the tag list with counts narrows the tree to
the pages that have all the chosen tags, shown as chips over it. A tag's ⋯
renames (in the Tags dialog), merges or deletes it; the Tags dialog, from
the tag list and the Space switcher, renames in a row and merges or deletes
several. Other pages change only in their `tags` key, through `relink`; the
open page changes in its editor.

**Checks:** `npm test` 2,738 passed and 1 skipped (211 files); `npm run
browser` 449 passed, twice in a row, exit 0, no unused references; 262
references in `testdata/visual/`, 10 new and the rest of the document,

**Deviations**

- **The prose is kept as read when only the front matter changes**
  (`DocEditor.markdown`, `withFront`). Before, changing a page's lock or
  width retidied hand-written prose; `docs/file-format.md` says prose is
  tidied when it is edited. An existing test changed to match.
- **The tree is narrowed through its `folders` map** as well as its rows
  (`foldersOf`): `SpaceTree` draws from the map. While narrowed, folders do
  not fold and nothing can be dragged.
- **Suggestions open above the field**: the tags row ends the page, and on
  a short page that is the window's bottom, where a list below would be
  cut off.
- **The Tags dialog is mounted only while open**, so a rename it opens for
  has the dialog's first focus (`data-autofocus`).
- **A menu's items and target are kept past its close** (the tag list's
  and the dialog's): the close can arrive before the choice, which then
  found no item and no tags (a flaky integration test showed it).
- **The confirmation's answer can be drawn as danger**; Delete uses it, as
  in the approved mockup.
- **Tokens added:** `--color-tag`, `--size-tag-field`, `--size-tag-filter`,
  `--size-check`, `--size-tag-count`; an icon, `tag`.
- **Rename asks nothing**: it cannot lose anything, and a taken name is
  refused where it is typed.

**Review:** one blocker, fixed: a tag holding `"` did not read back from
what Bava wrote (a flow list's `\"` closed the quote). Also fixed: tags
YAML would read as booleans, null or numbers are quoted; a comment after
the list is read past; a page with Windows line endings keeps them when
only its header is rewritten (specified); Backspace in an empty tag field
reaches the last chip; a locked page is left alone by a change across the
Space and named (specified); ConfirmDialog's look is one `tone`; the chip
is one component, `TagChip`; "1 tag · 1 page"; the tag list's own height
token; the tag colour's place in the token file; the tree helper's
comment; the highlighted suggestion and tag row announced
(`aria-activedescendant`); the dialog's checkboxes take the accent and
focus ring. Left: merging from the dialog's bar is covered by the browser
test only, as Ark's menu does not open under jsdom; the tag code in
`App.svelte` stays there, beside the rest of the side pane's.

**Left to a person at a running window:** the tags row and its field by
keyboard and screen reader on each platform's webview, the filter with a
large Space, and the end-to-end `create` walk's tag steps on CI.
