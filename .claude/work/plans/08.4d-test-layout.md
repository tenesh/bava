# 08.4d: Test layout

**Goal:** every test sits in a folder named for its layer, with one area name
used everywhere, and every test passes unchanged before and after the move.
**Specs:** `docs/testing.md`, `.ai/rules/testing.md`, the testing comparison of
Excalidraw, tldraw, Penpot, BlockSuite and Konva (2026-10-04, summarised under
Background).
**File format impact:** none.
**UI impact:** none.

## Background

Today the layer of a browser test is not visible from where it lives:
`frontend/tests/visual/specs/` holds screenshot walks (`<area>.spec.ts`) and
behaviour walks with no screenshots (`<area>-actions.spec.ts`) side by side.
Test data sits in five places, and the test roots are split between `tests/`
and `frontend/tests/` with no stated rule. This plan only moves and renames.
Cutting the screenshots down (one sheet per family, states checked as data,
the coverage guards removed) is the next plan, built on this layout.

## The layers

| Layer | What it answers | Where | Runs |
|---|---|---|---|
| Unit | Is the logic right? Does simulated input on the canvas or page give the right data? | next to the code: `frontend/src/**/<module>.test.ts`, `internal/**/<name>_test.go` | host and CI |
| Integration | Does it behave right in a real browser (selection, focus, layout)? Asserts on data, never screenshots | `frontend/tests/integration/<area>.spec.ts` | Docker, host and CI |
| Visual regression | Does it still look the same? Screenshots only | `frontend/tests/visual/<area>[-<topic>].spec.ts` | Docker, host and CI |
| End-to-end | Does the real app run on each OS? | `tests/e2e/<scenario>.json` | CI only |

## Target layout

```
frontend/src/**/<module>.test.ts         unit (unchanged)
frontend/src/**/__fixtures__/            unit fixtures (unchanged)
internal/**/<name>_test.go               Go unit (unchanged)

frontend/tests/
  playwright.config.ts                   two projects: visual, integration
  helpers.ts                             shared by both projects
  visual/<area>[-<topic>].spec.ts
  integration/<area>.spec.ts
  harness/                               the stand-in app the browser opens
  fixtures/                              scenes, pages and the sample Space
  .results/                              ignored output

tests/
  e2e/<scenario>.json
  docker/  scripts/

testdata/
  golden/                                D2 layout references (unchanged)
  visual/<area>[-<topic>]/<subject>--<state>--<theme>.png
  fixtures/media/  fixtures/links/       input files
```

Area names, the same in spec files, reference folders and test titles:
`canvas`, `components`, `dialogs`, `document`, `settings`, `shell`, `space`,
`start`. A topic splits an area that is too large for one file
(`canvas-elements`, `document-blocks`).

## Constraints

- No git write operations; files are moved with `mv`, and the user commits.
- Every count is the same after as before: Vitest tests, Go tests, Playwright
  tests (881 today), and every reference compared (orphans: none).
- Screenshot comparison stays `maxDiffPixels: 0`, `threshold: 0.02`.
- The e2e scenarios keep their contents; only their folder changes.
- Plans under `.claude/work/plans/` are history and are not rewritten.

## As built

The boxes above were left unticked; this section is the record of what
was done.

- **Task 1 went further than planned.** The held double-click
  (`selectWord`) fixed the word flake: 1 failure in 2,360 runs before, none
  in 2,360 after. Repeating the selected walks also found the table walk
  "four cells selected, their menu, and merged" failing 2 to 6 times in 80,
  and that was a real bug: after a choice in the Document's right-click menu,
  the closing menu could take focus back and drop it on the page body, so
  typing went nowhere and the browser's own highlight showed over selected
  cells. `ContextMenu` now reports `onClosed` once it has left the page
  (Ark's `onExitComplete`, a microtask later), and `DocumentPane` gives the
  editor focus there instead of on the close request. Test:
  `components/context-menu-close.svelte.test.ts`; the walk asserts the page
  has focus and hides the browser's highlight; 80 of 80 after. The canvas
  and Files menus give no focus back on close and were left as they are.
- **The orphan list** counts a run of a project other than `visual` as not
  full (`harness/orphans.ts`, tested), so `--project=integration` lists
  nothing.
- **Also renamed**, for one name throughout: `tests/docker/visual.Dockerfile`
  to `browser.Dockerfile`, its image `bava-visual` to `bava-browser`, and the
  CI job `screen checks` to `browser tests` (artifact `browser-test-results`).
- **A stale path fixed on the way:** `.ai/rules/design-system.md` named a
  `click-away.spec.ts` that no longer existed; it now names
  `integration/components.spec.ts`.
- `frontend/src/docs/__fixtures__/pages/testing.md` still shows the old
  layout: it is a fixture page's text, not documentation.
- Counts: Vitest 2,599 (2,596 + the three new tests), Go 392 as before,
  browser 881 (742 visual, 139 integration) with the same titles apart from
  `the component gallery` becoming `the components`.
- The orphan list collects every `--project` name (after `=`, repeated, or as
  the words that follow) and counts a run as full when `visual` is among
  them. `galleryShot` is `componentShot`; the harness page keeps the name
  `gallery`. Comments that said "screen checks" say "browser tests".
  `.gitattributes` needed no change.
- **Verification.** Host gates exit 0: check, lint, `npm test` (2,599 passed,
  1 skipped), `go vet`, `go test` (392 passing tests, as before). Browser
  runs, full: four runs after the move, two green (881 passed, no unused
  references) and two with flakes, never the same pair in a row:
  - `document-blocks › callout, being edited`: the selected word painted in
    WebKit's active-window highlight where the reference has the inactive
    one. The page's focus is in the editor in every run (probed 60 times);
    what varies is whether headless WebKit treats its window as active,
    which a test cannot set. It fails 5 in 120 with the held double-click
    and 5 in 120 without, so it predates this plan: the 0.2 tolerance hid
    it, and 0.02 shows it.
  - `integration/canvas › a selection exports alone, smaller than the
    canvas`: once, the selection's export was as wide as the canvas's (452).
  Both are left for the next plan, which redoes the selection pictures and
  the canvas walks.
