# 15.4d: SQL tables and UML classes on the canvas

**Goal:** Diagram from Code becomes "D2 diagram", and what adds to the
canvas is grouped in the Canvas menu; then a SQL table and a UML class are
canvas elements, typed as lines, added from a Diagram group or arriving
from a D2 diagram, with arrows that attach to a table's rows.
**Specs:** `.claude/work/specs/canvas-work.md` decisions 13 to 18;
`docs/file-format.md`; `.ai/rules/canvas.md`, `.ai/rules/d2.md`.
**File format impact:** two element types, `table` and `class`, and a row
on an arrow's binding (below), with round-trip tests.
**UI impact:** drawn as the mockup's "4.11 Tables and classes", "4.12
Typing a table" and "4.13 The Diagram category"; the menu as below.

Two parts, each its own commit and CI run: part 1 the rename and the menu,
part 2 tables and classes.

## Constraints

- "A double-click opens the whole body as text, one row a line, and leaving
  draws it." (13)
- "The element stores its name and its rows as one text, exactly as
  written; the columns are worked out each time it is drawn." (14)
- "Dropped on a row, it attaches beside that row and follows it when rows
  above are added or removed; a D2 diagram's links between columns arrive
  this way." (15)
- "A line with ( ) is a method, any other a field; fields are drawn above a
  divider and methods below, whatever order they were typed in. A leading
  +, -, # or ~ is public, private, protected or package." (16)
- "The + panel's new 'Diagram' category holds D2 diagram, SQL table and UML
  class. A table or class is placed by a click or a drag, as a shape is,
  and opens for typing at once. D2's `sql_table` and `class` convert into
  them. No rail button or key of their own." (17)
- "'D2 diagram' everywhere: the menu, the + panel, the page's / menu, the
  dialog, the code's names, file names and living docs (names stored on
  disk, past plans, specs and decision rows unchanged). File ▸ Diagram from
  Code and File ▸ Picture move to the top of the Canvas menu: a Diagram
  submenu (D2 Diagram, SQL Table, UML Class) and Picture, all in the
  command palette." (18)

# Part 2: tables and classes

## How it works

- **The elements** (file format):
  `{ "type": "table", "name": "users", "rows": "id int pk\nemail text unique", "x", "y", "w", "h", "z" }`
  and the same with `"type": "class"`. `rows` is the text as typed, one row
  a line. They take `fill`, `stroke`, `color` (the words), `strokeWidth`,
  `strokeStyle`, `opacity`, `angle`, `locked`, `frame`. Unknown keys kept.
- **A table row** reads `name type… keys`: the first word the column's
  name, trailing words among `pk`, `fk`, `unique`, `unq`, `primary_key`,
  `foreign_key` (any case) its keys, drawn PK, FK, UNQ; what lies between is
  its type, as typed ("varchar(255)", "double precision"). A blank line is
  skipped.
- **A class row**: an optional leading `+ - # ~`; with `(` it is a method,
  else a field. A field splits at its first `:` into name and type; a method
  at the first `:` after its closing bracket into name and return. Fields
  are drawn first, then a divider, then methods, each in typed order.
- **Drawn** (`table-layout.ts`, one layout for the stage and the SVG
  export): a box in the shape's paint, a header holding the name (bold; a
  table's at the left, a class's centred), a rule under it, then a row
  every `TABLE_ROW` (28): name at the left, type right-aligned before the
  keys column, keys at the right edge. Rows wider than the box are cut at
  its edge. The height is the rows' (`h` stored, recomputed when the rows
  change); resizing keeps the width the user's and never makes it shorter
  than its rows.
- **Typing**: a double-click opens the field over it (the label editor in
  free-text mode, mono), its first line the name and each line after it a
  row; leaving writes `name` and `rows` and the new height as one undo
  step. Emptied, the element is removed, as emptied text is.
- **Arrows to a row**: an arrow end dropped on a table's row (or a class's)
  records it beside its binding: `startRow` / `endRow`, the row's name (a
  table column's name; a class member's name without its marker). The end
  is pinned on the side facing the other end, at that row's middle, and
  follows the row wherever it moves. A row that is gone (renamed or
  deleted) leaves the end on the table as a whole, the row kept in the
  file, and it re-attaches if the row returns, as a binding does.
- **Added by hand**: the + panel's Diagram category and the Canvas menu's
  Diagram submenu gain SQL table and UML class (tools `table` and `class`,
  no key, no rail button). A click
  places one at `TABLE_START_WIDTH`, a drag at the width dragged; it starts
  with a name and one row (`table` / `id int pk`; `Class` / `+ name:
  string`) and opens for typing.
- **From a D2 diagram**: Go's layout gives each `sql_table` and `class`
  its rows as typed lines (`LayoutShape.rows`), from D2's columns, fields
  and methods; the frontend makes a `table` or `class` element at D2's box.
  An edge whose route ends on a table's row gets that row
  (`startRow`/`endRow`), worked out from where the route ends.
- **Found**: Search on the Space and find on the canvas read `name` and
  `rows`.

### Part 2

- `table` and `class` store `name` and `rows` as typed; `table-rows.ts`
  reads them (a quoted column name keeps its spaces), `table-layout.ts` lays
  them out for the stage, the SVG export, the height and binding. The
  layout takes the canvas's word measure: the keys column is as wide as its
  widest keys, and a name that would reach its type is cut with an
  ellipsis, the row still bound by its whole name.
- Painted as a shape (fill, stroke, words) with `--radius-md` corners; the
  name bold at `--text-body`, the rows mono at `--text-code`, keys at
  `--text-mono-chip`.
- Typing: the label editor in free-text mode, mono (`editTable`,
  `commitTable`, `tableText`). Leaving it as it opened records nothing; a
  change of rows makes the height theirs, a change of name alone keeps the
  height the user gave it. A resize keeps the width asked and never a height
  below the rows. Placing one and typing in it are two undo steps, as for a
  code block.
- Rows on arrows: `startRow`/`endRow` set where an end is dropped (the point
  the target was found at, Shift included) and dropped wherever the binding
  is. `rowAnchored` pins the end at route time, never stored: on the side
  facing the next bend, or for an elbow the other end, at the row's middle,
  the usual gap off a straight or curved arrow's end (an elbow's router
  keeps its own). Of two rows with one name, the first.
- Tools `table` and `class`: no key, no rail button; Canvas ▸ Diagram ▸ SQL
  Table and UML Class, and the + panel's Diagram category ("D2 diagrams, SQL
  tables and UML classes"). A click places one 240 wide; a drag gives the
  width dragged, never under 80. They start as `table` / `id int pk` and
  `Class` / `+ name: string`.
- From a D2 diagram: Go gives each `sql_table` and `class` its rows
  (`LayoutShape.rows`: other constraints kept before the keys, a spaced
  name quoted, a `void` return left out) and each link the columns it joins
  (`LayoutConnection.srcColumn`, `dstColumn`, from D2's graph), which become
  the arrow's rows; a link to a whole table gets none.
- Search on the Space and find on the canvas read name and rows.
- Pictured: the tables scene and a table selected, both themes. The other
  states (typed into, turned, locked, erased) are not pictured, as for
  pictures; they are tested as data.
