# D2

Using D2, which previews and lays out the D2 diagram only. It never lays out
the canvas, and the source is not kept.

## Import path and layout
`github.com/d2lang/d2`, pinned at v0.9.0; `oss.terrastruct.com/d2` is dead.
`textmeasure` lives at `lib/textmeasure`, not `d2renderers/textmeasure`.

## Library, never the binary
Never `exec.Command("d2", ...)`: it loses error positions and adds a runtime
dependency.

## Every Compile needs a logger
Without one, `d2lib.Compile` dumps a stack trace to stderr. Always
`ctx = d2log.With(ctx, logger)` (`github.com/d2lang/d2/lib/log`); a bare
`context.Background()` reaching `Compile` is a bug.

## TALA is the default engine
dagre and elk are user choices, not fallbacks. TALA ignores `direction`, so
never offer it while TALA is active. Only TALA honours `top`/`left`; Bava
never writes them.

## Layout timings
v0.9.0, ~25 nodes, warm: dagre 12ms, elk 7ms, TALA 96ms. They justify the flat
250ms debounce. Re-measure after a version bump.

## FS scoping
`CompileOptions.FS` stays nil unless `@import` is needed; then root it with
`lib/localfile`, or a `.d2` file can read anywhere on disk.

## Expansion budgets
Leave `MaxVariableExpansion`, `MaxGlobExpansion` and `MaxEdgeExpansion` at zero
(the secure defaults). Raising one needs a stated reason in the commit.

## data-d2-version is stale
The version in output SVGs reports v0.8.1-HEAD under v0.9.0. Never branch on
it or use it as a cache key.
