# D2

## Scope: `diagram` elements, not the app
D2 renders the `diagram` elements placed on a canvas. It does not lay out the
canvas, and the scene never round-trips through it. Everything below applies
inside that boundary.

Note for anyone reading a `.d2` file with `top`/`left` in it: those keywords
are honoured by **TALA only** — measured 2026-09-16, dagre and elk ignore them
and place everything at the origin. Bava does not write them; positions live in
the scene, on the element.

## Import path
`github.com/d2lang/d2`, pinned at v0.9.0. The old `oss.terrastruct.com/d2`
path is dead — the project moved orgs. Any example using it predates the move
and its API will not match. Package layout also changed: `textmeasure` lives
at `lib/textmeasure`, not `d2renderers/textmeasure`.

## Library, never the binary
D2 is used as a Go library. Never `exec.Command("d2", ...)`. Shelling out
gives up error positions, costs a process per render, and adds a runtime
dependency users would have to install.

## Every Compile needs a logger
`d2lib.Compile` pulls an `slog.Logger` from the context and dumps a full stack
trace to stderr when there isn't one. Always:

```go
ctx = d2log.With(ctx, logger)   // d2log "github.com/d2lang/d2/lib/log"
```

A bare `context.Background()` reaching `Compile` is a bug, not a style issue.

## TALA is the default engine
dagre and elk are user-selectable alternatives, not fallbacks. TALA produces
markedly more compact architecture layouts — measured on a ~25 node diagram it
was under half the width of both others.

TALA ignores `direction`. Do not expose `direction` as a control while TALA is
the active engine; it will silently do nothing.

## Layout timings
Measured, ~25 node architecture diagram, warm: dagre 12ms, elk 7ms, TALA 96ms.
This is what justifies the flat 250ms debounce and a single engine while
typing. Re-measure before assuming these still hold after a version bump.

## FS scoping
`CompileOptions.FS` is nil unless `@import` support is needed. When it is,
root it via `lib/localfile`. An unrooted FS handling user-supplied paths lets
a `.d2` file read anywhere on disk.

## Expansion budgets
Leave `MaxVariableExpansion`, `MaxGlobExpansion` and `MaxEdgeExpansion` at
zero — that selects the secure compiler defaults. Raising one needs a stated
reason in the commit.

## data-d2-version is stale
The version string embedded in output SVG is set at build time for the CLI and
does not track the module version. Ours reports v0.8.1-HEAD while running
v0.9.0. Never branch on it, and never use it as a cache key.
